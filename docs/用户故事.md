## 2. 角色定义

| 角色 | 说明 | 典型诉求 |
| --- | --- | --- |
| 组织者 / 管理员 | 负责开通云资源、维护成员与共享秩序 | 稳定可用、权限简单、上传整理方便 |
| 成员 | 被邀请加入共享空间的家人或协作者 | 浏览、下载、上传、删除、预览 |
| Android 用户 | 以手机为主的使用方 | 相册分享快捷、操作符合手机习惯 |
| macOS 用户 | 以电脑为主的整理方 | 宽屏浏览、拖拽上传、批量整理 |

说明：

- 一期不区分管理员与普通成员，所有登录用户权限相同。
- 最终权限以云端 OSS / RAM 为准，客户端只负责能力展示与交互收敛。

## 3. 故事优先级约定

- **P0**：一期必须具备，缺失则无法完成最小闭环
- **P1**：一期强烈建议具备，显著影响体验
- **P2**：可延后到体验增强阶段

## 4. 用户故事清单

### US-01 登录进入共享空间

- 优先级：P0
- 角色：管理员 / 普通成员
- 故事：作为一个共享空间成员，我希望用账号完成登录并进入文件空间，以便开始查看和传输文件。
- 业务价值：建立可信会话，是所有后续操作的入口。

**前置条件**

- 用户已有可用账号
- 轻后端可签发临时凭证

**主成功路径**

1. 用户打开 App
2. 输入账号和口令并登录
3. App 获取身份信息与 STS 临时凭证
4. 用户进入共享文件列表页

**扩展 / 异常路径**

- 账号或口令错误：停留在登录页，展示明确失败原因
- 网络异常：提示网络问题，允许重试
- 凭证签发失败：提示服务暂不可用，允许重试
- 已有有效会话：可直接进入文件空间

**验收标准**

- Android 与 macOS 均可完成登录
- 登录成功后 3 秒内进入文件列表
- 登录失败时不进入业务页，且错误提示可理解
- 不在客户端保存高权限永久密钥

---

### US-02 浏览目录与文件

- 优先级：P0
- 角色：管理员 / 普通成员
- 故事：作为一个共享空间成员，我希望按目录层级浏览文件，并看到名称、类型、大小和更新时间，以便快速定位资料。
- 业务价值：共享空间的基础可用性。

**前置条件**

- 用户已登录且会话有效

**主成功路径**

1. 用户进入共享根目录
2. 查看当前目录文件与文件夹
3. 点击文件夹进入下级
4. 返回上级目录
5. 手动刷新列表

**扩展 / 异常路径**

- 目录为空：展示空状态，并在有权限时给出上传/新建引导
- 列表加载失败：展示错误与重试
- 会话失效：提示恢复会话或重新登录

**验收标准**

- 能稳定完成目录进入与返回
- 列表展示名称、类型、大小、更新时间（文件夹可不显示大小）
- 空目录提示清晰
- 列表内容与 OSS 实际前缀保持一致

---

### US-03 新建文件夹

- 优先级：P0
- 角色：管理员（一期默认）；普通成员视能力配置
- 故事：作为一个有整理权限的成员，我希望新建文件夹，以便按主题归类文件。
- 业务价值：支撑基本目录管理。

**前置条件**

- 用户已登录
- 当前身份具备上传/创建能力

**主成功路径**

1. 用户在当前目录选择“新建文件夹”
2. 输入文件夹名称
3. 创建成功后列表出现新文件夹

**扩展 / 异常路径**

- 名称为空或非法：阻止提交并提示
- 同名冲突：提示已存在
- 无权限：不展示入口，或点击后提示权限不足

**验收标准**

- 有权限用户可成功创建文件夹
- 无权限用户无法创建
- 创建后无需重启 App 即可看到结果

---

### US-04 上传文件到指定目录

- 优先级：P0
- 角色：管理员（一期默认）；普通成员视能力配置
- 故事：作为一个有上传权限的成员，我希望把本地文件上传到当前目录，以便与其他成员共享。
- 业务价值：内容进入共享空间的核心路径。

**前置条件**

- 用户已登录且具备上传能力
- 已定位到目标目录

**主成功路径**

1. 用户选择上传入口
2. 通过系统文件选择器或相册选择文件
3. 开始上传并看到进度
4. 上传成功后文件出现在当前目录
5. 可在传输任务中查看结果

**扩展 / 异常路径**

- 网络中断：任务失败，支持重试
- 大文件：走分片上传
- 无上传权限：隐藏入口或明确拒绝

**验收标准**

- Android 支持文件选择与相册选择
- macOS 支持文件选择
- 上传进度、成功、失败状态可见
- 失败可重试

---

### US-05 macOS 拖拽上传

- 优先级：P1
- 角色：macOS 用户 / 管理员
- 故事：作为一个 macOS 用户，我希望把文件拖进窗口即可上传，以便更高效整理资料。
- 业务价值：桌面端高频效率能力。

**前置条件**

- 用户在 macOS 已登录
- 当前身份具备上传能力

**主成功路径**

1. 用户打开目标目录
2. 从访达拖拽一个或多个文件到上传区域
3. 系统创建上传任务并展示进度
4. 完成后列表刷新

**扩展 / 异常路径**

- 拖入不支持的内容：给出提示
- 无权限：拒绝并提示

**验收标准**

- 至少一个文件可通过拖拽完成上传
- 拖拽上传与普通上传进入同一任务体系

---

### US-06 下载文件到本地

- 优先级：P0
- 角色：管理员 / 普通成员
- 故事：作为一个共享空间成员，我希望把需要的文件下载到本地，以便离线查看或二次使用。
- 业务价值：共享内容真正可用。

**前置条件**

- 用户已登录
- 目标是文件而非文件夹

**主成功路径**

1. 用户在列表或预览页点击下载
2. App 创建下载任务并展示进度
3. 下载完成后用户可在本地找到文件

**扩展 / 异常路径**

- 下载失败：可重试
- 权限不足：提示无法下载
- 存储空间不足：提示失败原因

**验收标准**

- Android 与 macOS 均可完成下载
- 下载状态可追踪
- 成功后本地可访问

### US-06A 批量下载与删除文件

- 优先级：P1
- 角色：管理员 / 普通成员（删除仅限具备删除权限者）
- 故事：作为使用 macOS 整理共享空间的成员，我希望多选文件后批量下载或删除，以便高效完成整理工作。

**验收标准**

- macOS 可通过常驻表头或条目复选框直接开始多选；表头支持未选、部分选中、全选和再次点击清空
- Android 保留长按进入多选、点击切换选择的触屏交互
- 多选工具区仅展示当前身份有权使用的下载和删除动作
- 批量下载只创建多个独立文件任务，不生成压缩包；文件夹会被跳过并提示
- 批量删除前展示不可恢复警告及受影响对象数量；部分失败可明确获知
- 传输中心可配置 1 至 5 的总并发数，默认 3

### US-07 预览常见文件

- 优先级：P0
- 角色：管理员 / 普通成员
- 故事：作为一个共享空间成员，我希望直接预览图片、PDF 和文本，以便快速确认内容而不必先下载。
- 业务价值：降低查看成本。

**前置条件**

- 用户已登录
- 文件类型属于一期支持范围

**主成功路径**

1. 用户点击文件
2. App 按类型打开预览页
3. 用户可查看内容，并按需下载

**扩展 / 异常路径**

- 不支持预览：提示仅可下载
- 文件损坏或加载失败：展示错误态
- 文本过大：可截断并提示

**验收标准**

- 图片、PDF、文本均可预览
- 不支持类型有明确说明
- 预览页可返回列表

---

### US-08 重命名文件或文件夹

- 优先级：P1
- 角色：管理员（一期默认）
- 故事：作为一个有管理权限的成员，我希望重命名文件或文件夹，以便保持共享空间命名清晰。
- 业务价值：基础内容治理。

**前置条件**

- 用户已登录且具备相应能力

**主成功路径**

1. 用户打开对象操作菜单
2. 选择重命名并提交新名称
3. 列表显示新名称

**扩展 / 异常路径**

- 新名称为空、非法或冲突：阻止并提示
- 无权限：无入口或操作失败提示

**验收标准**

- 有权限时可完成重命名
- 重命名后路径关系正确，子目录不丢失
- 无权限时不能成功改名

---

### US-09 删除文件或文件夹

- 优先级：P1
- 角色：管理员（一期默认）
- 故事：作为一个有删除权限的成员，我希望删除不再需要的内容，以便保持共享空间整洁。
- 业务价值：基础清理能力。

**前置条件**

- 用户已登录且具备删除能力

**主成功路径**

1. 用户选择删除
2. App 弹出二次确认
3. 用户确认后执行删除
4. 列表移除对应项

**扩展 / 异常路径**

- 用户取消确认：不删除
- 删除失败：保留原对象并提示原因
- 无权限：无入口或失败提示

**验收标准**

- 删除必须二次确认
- 一期无回收站，文案需明确告知
- 有权限可删，无权限不可删

---

### US-10 按权限显示操作

- 优先级：P0
- 角色：管理员 / 普通成员
- 故事：作为一个共享空间成员，我希望只看到自己能做的操作，以免误点无权限功能。
- 业务价值：降低误操作与理解成本。

**前置条件**

- 用户已登录
- App 已拿到当前能力信息

**主成功路径**

1. 管理员看到浏览、下载、上传、删除等入口
2. 所有成员默认看到完整文件操作入口
3. 角色或能力变化后，界面同步收敛

**扩展 / 异常路径**

- 前端误显示某入口，但云端拒绝：提示权限不足
- 能力信息获取失败：采用安全默认策略并提示

**验收标准**

- 无权限操作默认隐藏或禁用
- 云端拒绝时有明确提示
- 不把客户端显示当作最终鉴权

### US-11 Android 系统分享导入

- 优先级：P0
- 角色：Android 用户 / 有上传权限成员
- 故事：作为一个 Android 用户，我希望在相册批量选图后通过系统分享发送到本 App，并选择上传目录，以便快速把照片放入正确位置。
- 业务价值：手机端最高频的内容导入路径之一。

**前置条件**

- 设备为 Android
- App 已注册系统分享入口
- 用户具备上传能力；若未登录需先登录

**主成功路径**

1. 用户在系统相册多选图片
2. 打开系统分享面板并选择“私域网盘”
3. App 打开分享确认页并展示待上传列表
4. 用户选择目标文件夹
5. 用户确认上传
6. App 创建上传任务，可在传输页查看进度

**扩展 / 异常路径**

- 未登录或会话失效：先登录/恢复会话，再回到确认页，不丢待上传列表
- 无上传权限：明确提示且不创建任务
- 用户移除部分图片后确认：仅上传保留项
- 冷启动与热启动分享均可进入确认页

**验收标准**

- 系统分享面板可见本 App
- 支持单张与多张图片分享
- 必须先选目录再上传
- 上传后文件出现在目标目录，任务可追踪

### US-12 查看与管理传输任务

- 优先级：P1
- 角色：管理员 / 普通成员
- 故事：作为一个正在传输文件的用户，我希望集中查看上传下载进度，并在失败时重试或取消，以便掌握结果。
- 业务价值：传输过程可感知、可恢复。

**前置条件**

- 用户已登录
- 存在进行中、成功或失败的任务

**主成功路径**

1. 用户进入传输页
2. 查看任务名称、方向、进度、状态与目标位置
3. 对失败任务执行重试
4. 对不需要的任务执行取消

**扩展 / 异常路径**

- 无任务：展示空状态
- 重试后再次失败：保持失败态并保留原因

**验收标准**

- 上传与下载任务均可展示
- 失败可重试，运行中/失败任务可取消
- 状态文案清晰，不依赖猜测

### US-13 会话失效后恢复

- 优先级：P0
- 角色：管理员 / 普通成员
- 故事：作为一个正在使用 App 的成员，我希望在临时凭证过期时被明确提示并能恢复会话，以免操作静默失败。
- 业务价值：保障连续使用与错误可理解。

**前置条件**

- 用户曾登录成功
- 临时凭证已过期或失效

**主成功路径**

1. 用户触发需要鉴权的操作
2. App 识别会话失效并提示
3. 用户确认恢复会话或重新登录
4. 恢复后可继续原业务

**扩展 / 异常路径**

- 自动刷新成功：用户无感或仅短暂等待
- 恢复失败：回到登录页

**验收标准**

- 不出现无提示的静默失败
- 恢复路径明确
- 分享导入等中断流程可在恢复后继续

---

### US-14 Android 移动端一致体验

- 优先级：P1
- 角色：Android 用户
- 故事：作为一个 Android 用户，我希望登录、文件、传输、预览、我的等页面风格一致，并符合手机操作习惯，而不是桌面端界面的缩小版。
- 业务价值：降低学习成本，提升日常使用舒适度。

**前置条件**

- 用户在 Android 设备使用 App

**主成功路径**

1. 用户在浅色或深色模式下浏览主要页面
2. 通过应用栏、列表、FAB、底部导航完成核心操作
3. 通过点击、长按或更多菜单完成文件操作，而不是依赖悬停

**扩展 / 异常路径**

- 系统切换深浅色：页面主题保持一致语言
- 窄屏设备：关键操作仍可触达，不出现桌面式拥挤工具条

**验收标准**

- 主要页面无突兀主题跳变
- 文件关键操作不依赖 hover
- 信息结构与 macOS 保持一致，但交互形态允许平台差异

### US-15 管理员不在 App 内维护复杂后台

- 优先级：P0
- 角色：组织者 / 管理员
- 故事：作为一个共享空间组织者，我希望成员权限主要通过阿里云侧配置完成，而不是在 App 内维护复杂后台，以便降低运营成本。
- 业务价值：符合轻量私域定位。

**前置条件**

- 组织者可访问阿里云 RAM / OSS 配置

**主成功路径**

1. 组织者在云侧完成成员与授权配置
2. 成员在 App 登录后获得对应能力
3. App 仅展示能力结果，不提供复杂角色编排后台

**验收标准**

- 一期 App 内不提供成员审批、角色矩阵、细粒度 ACL 编排
- 权限变化最终以云端鉴权结果为准

### US-16 切换目录浏览方式（列表 / 缩略图）

- 优先级：P1
- 角色：管理员 / 普通成员
- 故事：作为一个共享空间成员，我希望在目录中切换“列表”或“缩略图”浏览方式，以便在查找图片时更直观，在管理混合文件时更清晰。
- 业务价值：提升图片密集目录的浏览效率，同时保留现有列表方式用于通用文件管理。

**前置条件**

- 用户已登录
- 当前位于某个目录的文件列表页

**主成功路径**

1. 用户在目录页看到浏览方式切换入口（如列表 / 缩略图）
2. 用户选择“列表”时，继续以现有列表方式展示名称、类型、大小、更新时间等信息
3. 用户选择“缩略图”时，目录以宫格/卡片方式展示
4. 图片类型文件展示图片缩略图
5. 非图片类型文件（文件夹、PDF、文本、其他）展示默认类型图标，不强行生成内容预览缩略图
6. 用户切换后，当前目录立即按新方式渲染

**扩展 / 异常路径**

- 目录中没有图片：缩略图模式下全部使用默认图标，仍可正常浏览
- 图片缩略图加载失败：回退为默认图片类型图标，不影响其他项展示
- 用户切换目录：默认沿用最近一次浏览方式，避免反复设置
- 窄屏设备：缩略图列数自适应，不出现明显挤压或点按困难

**规则说明**

- 浏览方式作用于“当前目录内容的展示形态”，不改变文件本身的权限与操作能力
- 缩略图模式仅对图片类型尝试展示真实缩略图
- 文件夹、PDF、文本、未知类型等使用统一的默认文件/类型图标
- 列表模式保留现有信息密度，适合混合文件管理与查看元信息
- 一期不要求视频封面、PDF 首页渲染、文件夹内容拼图等高级缩略能力

**验收标准**

- 用户可在列表与缩略图两种方式间切换
- 列表模式信息完整，不弱于现有浏览能力
- 缩略图模式下，图片显示缩略图；非图片显示默认图标；桌面卡片固定内容只含缩略图和单行文件名
- macOS 列表与缩略图通过右键菜单提供单文件打开或预览、下载、重命名、删除；右侧详情区只读
- macOS 上传文件入口只保留在文件页工具栏
- 图片缩略图失败时有稳定降级，不出现大面积空白或布局错乱
- 浏览方式偏好在应用会话内可保持；若实现成本可控，可本地持久化
