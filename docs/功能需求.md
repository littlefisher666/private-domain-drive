## 2. 功能需求

### 2.1 登录与身份识别

#### 功能描述

用户通过预设身份体系完成登录，App 获取当前身份并换取访问 OSS 的临时凭证。

#### 需求说明

- App 支持用户登录
- 登录成功后调用轻后端接口获取 STS 临时访问凭证
- App 能识别当前用户身份和基础能力信息
- 凭证过期后支持自动刷新或重新获取
- 登录失败需展示可理解原因，不进入业务页

#### 验收标准

- 用户可在 Android 和 macOS 成功登录
- 登录后 3 秒内完成凭证获取并进入文件列表页
- 账号口令错误、网络失败、服务失败均有明确提示
- 凭证失效后，App 能提示并恢复会话，不出现静默失败

#### 对应用户故事

- US-01、US-13

### 2.2 文件浏览与目录管理

#### 功能描述

用户可以查看共享空间内的目录和文件，并在权限允许时进行基础目录管理。

#### 需求说明

- 支持按目录层级浏览文件
- 支持显示文件名、大小、更新时间、文件类型
- 支持进入子目录、返回上级、手动刷新
- 空目录和空状态有清晰提示
- 支持切换目录浏览方式：列表 / 缩略图
- 列表模式沿用现有信息展示方式，适合查看名称与元信息
- 缩略图模式以宫格/卡片展示；仅图片类型显示真实缩略图，其他类型使用默认文件/类型图标
- macOS 文件区域左上角常驻三态复选框及加载数量；条目复选框在悬浮或已选时出现，可直接开始多选
- 多选时仅显示已授权的批量下载、删除动作；表头全选再次点击可清空当前目录选择
- macOS 列表和缩略图条目的单文件操作统一通过右键菜单提供；右侧详情区仅展示预览与基础元信息
- 图片详情预览展示 EXIF 拍摄日期；原图缺少该信息时保留空值，不以 OSS 更新时间替代
- macOS 缩略图卡片只保留缩略图和单行文件名，标题栏不再提供重复上传入口，上传文件入口保留在文件页工具栏
- 浏览方式切换不改变权限与可执行操作
- 文件列表支持按文件名、更新时间和图片拍摄时间升序或降序排序；排序规则按文件夹独立保存。文件夹始终置顶，缺少 EXIF 拍摄时间的文件在拍摄时间排序中置后并按更新时间兜底
- Android 在文件列表顶部提供排序入口并以底部菜单选择；macOS 在视图切换和刷新操作之间提供当前排序入口
- 有权限时可新建文件夹
- 有权限时可重命名文件/文件夹
- 有权限时可将文件/文件夹移入回收站，操作必须二次确认
- 回收站展示原位置、删除时间和预计清理日期；删除后 30 天内可恢复
- 回收站支持对单个回收批次立即删除，操作必须二次确认，删除后不可恢复
- Android 文件操作以点击、长按或更多菜单完成，不依赖 hover

#### 验收标准

- 目录切换响应顺畅
- 50GB 规模、正常目录结构下可稳定列出文件
- 文件列表与 OSS 实际内容保持一致
- 用户可在列表与缩略图两种浏览方式间切换
- 用户可选择文件列表排序方式；图片按拍摄时间排序时，缺少拍摄时间的文件可稳定回退排序
- 缩略图模式下图片显示缩略图，非图片显示默认图标
- 图片缩略图加载失败时回退为默认图标，不影响整体布局
- 新建、重命名、删除在有权限时可用，无权限时不可用
- 删除文案明确提示“移入回收站，30 天内可恢复”
- macOS 右键菜单按文件类型及权限展示操作，且删除仍需二次确认

#### 对应用户故事

- US-02、US-03、US-08、US-09、US-16

### 2.3 上传文件

#### 功能描述

有上传权限的用户可将本地文件上传到指定目录。

#### 需求说明

- Android 支持系统文件选择器上传
- Android 支持从相册选择图片上传
- Android 支持接收系统分享导入，详见 2.8
- macOS 支持文件选择与拖拽上传
- 显示上传进度、状态、失败重试
- 大文件需支持分片上传
- 无上传权限时隐藏入口或明确拒绝
- 上传成功后刷新目标目录，并写入传输任务

#### 验收标准

- 小文件上传成功率高
- 网络波动时上传失败可重试
- macOS 可通过拖拽上传至少一个文件
- Android 可完成文件选择上传与相册上传
- 上传任务状态可在传输中心查看

#### 对应用户故事

- US-04、US-05、US-12

### 2.4 下载文件

#### 功能描述

用户可将文件下载到本地设备。

#### 需求说明

- 支持选择下载保存位置或使用默认目录
- 显示下载进度和状态
- 下载失败支持重试
- 文件夹不支持直接当单文件下载（一期不做打包下载）
- 支持多选文件后一次选择目标目录；每个文件作为独立任务下载，不生成 ZIP
- 选中的文件夹会被跳过并明确提示；同名文件自动改名，不覆盖本地已有文件
- 传输中心可设置上传、下载共用的总并发数（1 至 5，默认 3）

#### 验收标准

- Android 和 macOS 均可完成下载
- 下载成功后用户可在本地找到文件
- 下载任务可追踪
- 批量下载可展示单文件进度及批次完成、失败、排队汇总

#### 对应用户故事

- US-06、US-12

### 2.5 文件预览

#### 功能描述

用户可预览部分常见文件。

#### 第一期开启范围

- 图片预览
- PDF 预览
- 文本预览

#### 第一期限制

- 不做 Office 在线编辑
- 不做复杂视频在线播放转码

#### 验收标准

- 图片可直接打开查看
- PDF 能正常加载
- 文本文件可显示基础内容
- 不支持类型有明确说明，并提供下载入口

#### 对应用户故事

- US-07

### 2.6 权限驱动的功能显示

#### 功能描述

App 根据用户当前能力渲染上传、下载、删除等入口。

#### 设计原则

- UI 层显示由 App 控制
- 最终访问控制以 OSS 云端鉴权结果为准
- 不在客户端单纯解析复杂 RAM Policy 作为唯一依据

#### 建议实现

- App 获取当前用户能力信息
- 对关键操作进行能力探测或服务端下发能力描述
- 根据能力结果渲染按钮

#### 验收标准

- 无权限操作不显示或不可点击
- 即使前端误显示，OSS 也能拒绝未授权请求
- 权限不足时提示明确

#### 对应用户故事

- US-10、US-15

### 2.7 错误处理与传输反馈

#### 需求说明

- 网络异常提示清晰
- 凭证失效可感知并可恢复
- OSS 权限不足时给出明确提示
- 上传、下载失败允许重试
- 传输中心展示进行中、成功、失败等状态
- 支持取消不需要继续的任务
- 传输中心支持配置上传、下载共用的总并发数（1 至 5，默认 3）

#### 验收标准

- 关键失败路径都有用户可理解的反馈
- 失败任务可重试
- 不出现无提示的静默失败

#### 对应用户故事

- US-12、US-13

### 2.8 Android 系统分享接入

#### 功能描述

用户可从系统相册或其他应用，通过 Android 系统分享面板将图片/文件发送到“私域网盘”，并在 App 内控制上传目标文件夹。

#### 需求说明

- 支持 `SEND` 与 `SEND_MULTIPLE` 分享入口
- 一期优先支持图片；如系统分享携带普通文件，也应尽量接收并进入同一导入流程
- 冷启动分享与热启动分享均直接弹出上传目录选择弹窗，不落地中间确认页
- 若用户未登录或会话失效，先完成登录/恢复会话，再弹出目录选择弹窗，不丢失待上传内容
- 目录选择弹窗默认定位共享空间根目录，支持逐级浏览并选定上传目录
- 确认目录后立即创建上传任务，取消则放弃本次导入并清空待上传内容
- 上传任务可在传输任务列表中查看进度与结果
- 本节仅覆盖“接收系统分享”，不做对外公开分享链接

#### 验收标准

- 相册多选图片后，系统分享面板中可看到本 App
- 分享进入后可选择文件夹并成功创建上传任务
- 未登录分享进入时，登录后仍能继续完成目录选择与上传
- 无上传权限时有明确失败提示，不产生无效任务
- 分享弹窗取消后不残留待上传项

#### 对应用户故事

- US-11

### 2.9 Android 视觉与交互一致性

#### 功能描述

Android 端各页面应形成统一的移动端视觉语言，避免“桌面布局硬缩到手机”的割裂感。

#### 需求说明

- 全应用统一浅色/深色主题，不允许部分页面长期硬编码另一套背景风格
- 文件列表采用移动端骨架：顶部应用栏、列表主体、上传主操作（FAB 或等价入口）、底部主导航
- 文件操作以点击进入、长按/更多菜单为主，不依赖鼠标悬停才显示操作
- 页面边距、字号、控件高度按触控场景设计
- 登录、文件、传输、预览、设置/我的页面保持同一套颜色、圆角、按钮和反馈样式
- macOS 可保留宽屏双栏/三栏与拖拽能力，但不要求 Android 复用同一套桌面交互

#### 验收标准

- 在系统浅色与深色模式下，主要页面风格一致
- Android 文件页不依赖 hover 才能完成预览、下载、删除等操作
- 从文件页进入传输、预览、设置后，不出现突兀的主题跳变

#### 对应用户故事

- US-14

## 3. 关键流程

### 3.1 登录与进入文件空间

1. 用户打开 App
2. 用户完成登录
3. App 调用轻后端接口
4. 轻后端校验身份并返回 STS 临时凭证
5. App 使用临时凭证访问 OSS
6. App 拉取文件列表并渲染首页

### 3.2 上传流程

1. 用户选择文件，或从系统分享进入并确认列表
2. App 校验目标目录和上传能力
3. App 使用临时凭证发起上传
4. 上传过程中显示进度
5. 上传成功后刷新文件列表，并更新传输任务

### 3.3 下载流程

1. 用户点击下载
2. App 获取下载地址或直接发起下载请求
3. 下载完成后保存至本地
4. App 给出成功反馈，并更新传输任务

### 3.4 删除流程

1. 用户选择删除
2. App 展示二次确认
3. 用户确认后发起删除
4. 成功后刷新列表；失败则提示原因

### 3.5 Android 系统分享上传流程

1. 用户在系统相册或其他 App 中选择一张或多张图片/文件
2. 用户打开系统分享面板并选择“私域网盘”
3. App 被系统拉起，登录就绪后直接弹出上传目录选择弹窗（默认定位根目录）
4. 若未登录或会话失效，先完成登录/恢复会话，再弹出目录选择弹窗
5. 用户浏览并选定目标目录后确认
6. App 立即创建上传任务并提示上传开始，可在传输页查看进度
7. 用户取消弹窗则放弃本次导入，不残留待上传项

## 4. 平台体验要求摘要

### 4.1 Android

- 支持系统文件选择器、相册选择、系统分享接收
- 适配窄屏触控
- 统一主题与导航骨架
- 正确处理前后台切换、分享冷/热启动、网络变化

### 4.2 macOS

- 支持宽屏布局
- 支持拖拽上传
- 支持更适合桌面的双栏或三栏布局

### 4.3 统一性

- 两端尽量共用业务逻辑
- UI 可根据屏幕宽度和平台做差异适配
- 不要求像素级一致，但信息结构与核心流程应统一

## 5. 非功能要求摘要

详细产品级非功能要求见 [PRD.md](./PRD.md)，技术实现约束见 [技术文档.md](./技术文档.md)。

这里只保留与功能验收直接相关的摘要：

- 登录后文件列表首屏尽量 3 秒内完成
- 列表滚动流畅，传输状态及时反馈
- 不持久化高权限永久密钥
- 删除需二次确认
- 普通成员不直接面对阿里云底层复杂概念
