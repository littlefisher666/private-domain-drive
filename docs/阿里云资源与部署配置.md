# 阿里云资源与部署配置指南

## 1. 文档概述

- 关联文档:[技术文档.md](./技术文档.md)、[接口.md](./接口.md)
- 文档类型:云资源创建 + 仓库配置 + CI Secrets 操作手册
- 认证模式:**双 AKSK 直连**(不再使用 STS AssumeRole)
  - 客户端在**登录时**经 bootstrap 从服务端获取一对 OSS AccessKey,在本次会话内直连 OSS,退出登录清除;客户端**不内置** OSS 密钥
  - 服务端(FC)持有一对长期 RAM AccessKey,只读写 OSS 用户目录;并代为保管客户端 OSS 密钥用于登录下发
- 客户端密钥方案:**B 方案(两套独立密钥)**
  - `PDD_CLIENT_OSS_*`:客户端直连 OSS,由服务端保管、登录时下发
  - `FC_ACCESS_KEY_*`:客户端签名调用 FC 登录接口(构建期注入)
  - 两套职责隔离,不合并

> 本文只覆盖**云资源、仓库配置、CI Secrets**。服务端/客户端源码对 `PDD_*` 的读取改造见后续代码变更,不在本文范围。

### 2.2 OSS Bucket `private-domain-drive`

路径:OSS 控制台 → Bucket 列表 → 创建 Bucket

| 字段 | 必填 | 建议值 |
|------|------|--------|
| Bucket 名称 | 必填 | `private-domain-drive`(全局唯一,不可改) |
| 地域 | 必填 | 华东1(杭州)`cn-hangzhou`,与 FC 同地域 |
| 存储类型 | 必填(有默认) | 标准存储 |
| 同城冗余 | 可选 | 关闭 |
| 版本控制 | 可选 | 关闭 |
| 读写权限(ACL) | 必填(有默认) | **私有** |
| 服务端加密 | 可选 | 无 / OSS 完全托管 |
| 实时日志 | 可选 | 关闭 |
| 定时备份 | 可选 | 关闭 |
| 传输加速 | 可选 | 关闭 |

创建后进入 Bucket → 文件管理,上传本地 `server/config/users.json` 到对象键 `config/users.json`。

### 2.3 权限策略(脚本编辑)

路径:RAM → 权限管理 → 权限策略 → 创建权限策略 → **脚本编辑**。

> ⚠️ FC 相关策略必须用**脚本编辑**。RAM 可视化编辑器的 FC 资源模板是 FC 2.0 老格式(`services/.../functions/...`),认不出 FC 3.0 的 `functions/<名称>`,会标为「未识别资源」。脚本编辑可绕开。

#### `pdd-client-oss`

- 名称(必填):`pdd-client-oss`
- 备注(可选):私域网盘客户端直连 OSS,限 `shared/` 前缀

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "oss:ListObjects",
        "oss:ListObjectVersions",
        "oss:GetObject",
        "oss:ProcessObject",
        "oss:PutObject",
        "oss:DeleteObject",
        "oss:AbortMultipartUpload",
        "oss:ListParts"
      ],
      "Resource": ["acs:oss:*:*:private-domain-drive/shared/*"]
    },
    {
      "Effect": "Allow",
      "Action": ["oss:ListObjects"],
      "Resource": ["acs:oss:*:*:private-domain-drive"],
      "Condition": {
        "StringLike": { "oss:Prefix": ["shared/*"] }
      }
    }
  ]
}
```

#### `pdd-server-oss`

- 名称(必填):`pdd-server-oss`
- 备注(可选):私域网盘服务端读写用户目录 `config/users.json`

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["oss:GetObject", "oss:PutObject"],
      "Resource": ["acs:oss:*:*:private-domain-drive/config/users.json"]
    }
  ]
}
```

#### `pdd-fc-invoke`

- 名称(必填):`pdd-fc-invoke`
- 备注(可选):私域网盘客户端签名调用 FC 登录接口

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["fc:InvokeFunction"],
      "Resource": ["acs:fc:cn-hangzhou:1360783690756788:functions/private-domain-drive"]
    }
  ]
}
```

#### `pdd-fc-deploy-passrole`

- 名称(必填):`pdd-fc-deploy-passrole`
- 备注(可选):私域网盘部署时向 FC 传递执行角色 `pdd-fc-role`

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["ram:PassRole"],
      "Resource": ["acs:ram::1360783690756788:role/pdd-fc-role"]
    }
  ]
}
```

### 2.4 RAM 用户(4 个)

路径:RAM → 身份管理 → 用户 → 创建用户。共用字段:

| 字段 | 必填 | 说明 |
|------|------|------|
| 登录名称 | 必填 | 见下表 |
| 显示名称 | 可选 | 见下表 |
| 访问方式 - 控制台访问 | 可选 | **都不勾** |
| 访问方式 - 永久 AccessKey | 必填 | **都勾**,生成 AKSK |
| MFA | 可选 | 不开启 |

| 用户 | 登录名称 | 显示名称(可选) | 授权策略 |
|------|---------|----------------|---------|
| 客户端 OSS | `pdd-client` | 私域网盘客户端 | `pdd-client-oss` |
| 服务端 | `pdd-server` | 私域网盘服务端 | `pdd-server-oss` |
| 部署 | `pdd-fc-deploy` | 私域网盘发布 | `AliyunFCFullAccess` + `AliyunLogFullAccess` + `pdd-fc-deploy-passrole` |
| FC 调用签名 | `pdd-fc-invoke` | 私域网盘FC调用签名 | `pdd-fc-invoke` |

每个用户创建后弹出 AccessKey ID / Secret,**Secret 只显示一次**,立即保存。

### 2.5 RAM 角色 `pdd-fc-role`

路径:RAM → 身份管理 → 角色 → 创建角色 → 可信实体类型选「阿里云服务」

| 字段 | 必填 | 值 |
|------|------|-----|
| 角色类型 | 必填 | 普通服务角色 |
| 角色名称 | 必填 | `pdd-fc-role` |
| 备注 | 可选 | 私域网盘 FC 函数执行角色 |
| 选择受信服务 | 必填 | 函数计算(FC) |

创建后 → 权限管理 → 新增授权 → 挂系统策略 `AliyunLogFullAccess`(新模式下 FC 角色只需写日志)。

## 4. 仓库配置文件清单

### 4.1 `server/.env` 与 `server/.env.example`(服务端运行时)

两者注释保持一致;`.env` 填真实值,`.env.example` 为占位模板。

| 变量 | 必填 | 说明 |
|------|------|------|
| `PDD_SERVER_OSS_ACCESS_KEY_ID` | 是 | `pdd-server` 的 AK |
| `PDD_SERVER_OSS_ACCESS_KEY_SECRET` | 是 | `pdd-server` 的 SK |
| `PDD_CLIENT_OSS_ACCESS_KEY_ID` | 是 | `pdd-client` 的 AK,服务端保管、登录时下发 |
| `PDD_CLIENT_OSS_ACCESS_KEY_SECRET` | 是 | `pdd-client` 的 SK,服务端保管、登录时下发 |
| `PDD_OSS_BUCKET` | 否 | `private-domain-drive` |
| `PDD_OSS_REGION` | 否 | `cn-hangzhou` |
| `PDD_OSS_ENDPOINT` | 否 | `oss-cn-hangzhou.aliyuncs.com` |
| `PDD_OSS_ROOT_PREFIX` | 否 | `shared/` |
| `PDD_TEXT_PREVIEW_MAX_BYTES` | 否 | 默认 `524288` |
| `PDD_MULTIPART_UPLOAD_THRESHOLD_BYTES` | 否 | 默认 `10485760` |
| `PDD_ALLOWED_PREVIEW_EXTENSIONS` | 否 | `jpg,jpeg,png,gif,pdf,txt,md` |
| `PORT` | 否 | 本地端口,默认 `9000` |

### 4.2 `server/s.yaml`(Serverless Devs)

- `region`: `cn-hangzhou`
- `functionName`: `private-domain-drive`
- `role`: `${env(PDD_FC_ROLE_ARN)}`
- `environmentVariables`: 注入 `PDD_SERVER_OSS_*`、`PDD_CLIENT_OSS_*`、`PDD_OSS_*`、`PDD_*` 约束项

### 4.3 `server/.github/workflows/deploy-fc.yml`(CI)

- Secrets 映射为 `PDD_DEPLOY_*`、`PDD_FC_ROLE_ARN`、`PDD_SERVER_OSS_*`、`PDD_CLIENT_OSS_*`
- 必需密钥校验清单同步为上述新名
- `s config add` 使用 `PDD_DEPLOY_*`

### 4.4 `client/env/local.json`(客户端)

| 键 | 说明 |
|----|------|
| `FC_BASE_URL` | FC HTTP 触发 URL |
| `FC_ACCESS_KEY_ID` / `FC_ACCESS_KEY_SECRET` | `pdd-fc-invoke` 的 AKSK(B 方案,签名用) |
| `FC_SIGN_REQUESTS` | 是否签名,`true` |
| `ALLOW_LOCAL_MOCK_FALLBACK` | 本地 mock 回退,`false` |
| `DEBUG_DEFAULT_ACCOUNT` / `DEBUG_DEFAULT_PASSWORD` | 调试账号口令 |

> 客户端**不**在 `local.json` 配置 OSS 密钥:OSS 的 AKSK 由服务端保管,登录 bootstrap 时下发,客户端仅在会话内持有。
> `FC_*` 键名暂不改(客户端代码以 dart-define 读取),改名留到代码改造阶段。

## 7. 注意事项

1. **配置与代码一致性**:服务端与客户端源码已完成双 AKSK 直连改造(bootstrap 下发 `clientCredentials`,已删除 STS 字段与 refresh 接口)。部署或本地运行前,确认 `.env` / `s.yaml` / CI Secrets 均按本文第 4、5 节的新变量名配置;旧 STS 变量已全部废弃。
2. **FC 策略用脚本编辑**:可视化编辑器不识别 FC 3.0 的 `functions/<名称>` ARN。
3. **密钥只出现一次**:RAM 用户 AccessKey Secret 仅在创建时显示,务必立即保存。
4. **最小权限**:客户端 OSS 权限锁定在 `shared/` 前缀;如客户端不需要删除,可从 `pdd-client-oss` 移除 `oss:DeleteObject`。
5. **`.env` 不入库**:`server/.env` 含真实密钥,已在 `.gitignore`,不要提交。
