# 接口文档

## 1. 文档说明

本文档描述 Private Domain Drive 一期轻后端（阿里云函数计算 FC）对外 HTTP 接口。

一期服务端职责仅包括：

- 登录校验与会话初始化
- 首次下发 STS 临时凭证 + stsBroker
- STS 凭证刷新（兜底，非常规热路径）
- 用户能力信息下发
- 健康检查

文件列表、上传、下载、删除、预览等文件流量接口**不经过业务后端**，由客户端持 STS 临时凭证直连阿里云 OSS 完成。

### 1.1 文档范围

| 范围 | 是否覆盖 |
| --- | --- |
| FC 控制面接口 | 是 |
| OSS 直连文件操作 | 否（仅说明边界） |
| 二期登录鉴权增强 | 仅备注，不作为一期正式契约 |

### 1.2 基础信息

| 项 | 说明 |
| --- | --- |
| 协议 | HTTP / HTTPS |
| 数据格式 | `application/json; charset=utf-8` |
| 路径前缀 | `/api/v1` |
| 部署形态 | 阿里云 FC HTTP 触发器 |
| 本地调试默认地址 | `http://127.0.0.1:9000` |

### 1.3 统一响应结构

所有业务接口均返回 JSON。成功与失败共用以下外壳字段：

| 参数名 | 参数类型 | 参数中文描述 | 是否必填 | 说明 |
| --- | --- | --- | --- | --- |
| code | string | 业务状态码 | 是 | 成功固定为 `OK` |
| message | string | 状态说明 | 是 | 成功一般为 `success` |
| requestId | string | 请求追踪 ID | 是 | 优先取 FC 请求 ID |
| data | object | 业务数据 | 否 | 仅成功时返回 |

成功响应外壳示例：

```json
{
  "code": "OK",
  "message": "success",
  "requestId": "req-20260810-0001",
  "data": {}
}
```

失败响应外壳示例：

```json
{
  "code": "BAD_REQUEST",
  "message": "Request body must be a JSON object",
  "requestId": "req-20260810-0002"
}
```

### 1.4 统一错误码

| code | HTTP 状态码 | 含义 | 典型场景 |
| --- | --- | --- | --- |
| OK | 200 | 成功 | 正常返回 |
| BAD_REQUEST | 400 | 请求参数错误 | body 非 JSON 对象、缺少 account/password |
| UNAUTHORIZED | 401 | 身份校验失败 | 账号或口令错误 |
| NOT_FOUND | 404 | 路由不存在 | 路径或 method 不匹配 |
| SERVICE_UNAVAILABLE | 503 | 服务暂不可用 | STS 相关配置缺失 |
| INTERNAL_ERROR | 500 | 服务内部错误 | 未捕获异常、STS 调用异常 |

### 1.5 通用约定

1. 请求与响应字段统一使用 **camelCase**。
2. 时间字段使用 `yyyy-MM-dd HH:mm:ss` 字符串，例如 `2026-06-05 12:00:00`。
3. 一期 bootstrap 通过 body 中的 account / password 做演示账号校验；暂不强制 Authorization Header。
4. 客户端拿到 STS 后，文件读写权限最终以 OSS / RAM Policy 鉴权结果为准；本接口返回的 `capabilities` 仅用于 UI 能力展示收敛。
5. STS 权限默认限制在配置的 bucket + rootPrefix 范围。
6. 方案 B：日常再次打开 App 时，客户端应使用本地缓存的 stsBroker 直连阿里云 STS 刷新临时凭证，避免每次打开都调用 FC。

## 3. 接口详情

### 3.1 健康检查

#### 接口说明

用于探活与运行时基础信息查询。可供本地调试、部署验收、监控探测使用。不依赖 STS 配置，不访问 OSS。

#### Method

`GET`

#### URI

`/api/v1/health`

#### 入参

无 Query、Path、Body 参数。

| 参数名 | 参数类型 | 参数中文描述 | 是否必填 | 其他校验要求 |
| --- | --- | --- | --- | --- |
| - | - | 本接口无业务入参 | - | - |

#### 出参

外层仍遵循统一响应结构。`data` 字段如下：

| 参数名 | 参数类型 | 参数中文描述 |
| --- | --- | --- |
| status | string | 服务状态，正常时为 `up` |
| version | string | 当前服务版本号 |
| runtime | string | 运行时标识，当前为 `nodejs20` |

#### 出参样例

```json
{
  "code": "OK",
  "message": "success",
  "requestId": "test-health",
  "data": {
    "status": "up",
    "version": "0.1.0",
    "runtime": "nodejs20"
  }
}
```

#### 备注

1. 该接口不校验业务身份。
2. 返回 200 仅表示 FC 函数可响应，不代表 STS 配置完整可用。
3. 若要验证 STS 是否可用，应调用 `/api/v1/session/bootstrap` 或 `/api/v1/session/refresh`。

### 3.2 会话初始化 / 获取临时凭证

#### 接口说明

客户端在登录成功或冷启动进入文件空间前调用。服务端基于当前身份（一期为配置映射身份）申请阿里云 STS 临时凭证，并一并返回：

- OSS 连接配置
- 当前用户信息
- 能力描述（`capabilities`）
- 客户端约束配置（`constraints`）

该接口是一期进入网盘主流程的核心控制面接口。

#### Method

`POST`

#### URI

`/api/v1/session/bootstrap`

#### 入参

Content-Type 建议：`application/json`

Body 必须是 JSON 对象。

| 参数名 | 参数类型 | 参数中文描述 | 是否必填 | 其他校验要求 |
| --- | --- | --- | --- | --- |
| account | string | 成员账号 | 是 | 演示账号：admin / member |
| password | string | 访问口令 | 是 | 演示口令：123456 |
| platform | string | 客户端平台标识 | 否 | 建议传 macos 或 android |
| appVersion | string | 客户端版本号 | 否 | 建议语义化版本字符串，如 0.1.0 |

> 说明：account / password 用于一期演示登录校验；platform、appVersion 便于后续版本兼容。

#### 出参

外层仍遵循统一响应结构。`data` 字段如下：

| 参数名 | 参数类型 | 参数中文描述 |
| --- | --- | --- |
| credentials | object | STS 临时凭证对象 |
| credentials.accessKeyId | string | 临时 AccessKeyId |
| credentials.accessKeySecret | string | 临时 AccessKeySecret |
| credentials.securityToken | string | 临时安全令牌 |
| credentials.expiration | string | 凭证过期时间（yyyy-MM-dd HH:mm:ss） |
| stsBroker | object | 客户端本地 AssumeRole 换票凭证（方案 B） |
| stsBroker.accessKeyId | string | 仅用于调用阿里云 STS 的 AccessKeyId |
| stsBroker.accessKeySecret | string | 仅用于调用阿里云 STS 的 AccessKeySecret |
| stsBroker.endpoint | string | STS endpoint |
| stsBroker.roleArn | string | 可 Assume 的角色 ARN |
| stsBroker.roleSessionName | string | 角色会话名 |
| stsBroker.durationSeconds | number | 申请临时凭证时长（秒） |
| stsBroker.policy | string | 会话策略 JSON 字符串 |
| oss | object | OSS 访问配置 |
| oss.bucket | string | OSS Bucket 名称 |
| oss.region | string | OSS 地域，如 `cn-hangzhou` |
| oss.endpoint | string | OSS Endpoint |
| oss.rootPrefix | string | 允许访问的根前缀，如 `shared/` |
| user | object | 当前用户信息 |
| user.userId | string | 用户 ID |
| user.displayName | string | 用户显示名 |
| user.role | string | 用户角色，如 `member`、`admin` |
| capabilities | object | 客户端能力开关，仅用于 UI 收敛 |
| capabilities.list | boolean | 是否允许列举文件 |
| capabilities.download | boolean | 是否允许下载 |
| capabilities.upload | boolean | 是否允许上传 |
| capabilities.delete | boolean | 是否允许删除 |
| capabilities.preview | boolean | 是否允许预览 |
| constraints | object | 客户端行为约束 |
| constraints.multipartUploadThresholdBytes | number | 超过该字节数建议走分片上传 |
| constraints.textPreviewMaxBytes | number | 文本预览允许的最大字节数 |
| constraints.allowedPreviewExtensions | string[] | 允许预览的扩展名白名单 |

#### 出参样例

```json
{
  "code": "OK",
  "message": "success",
  "requestId": "req-bootstrap-001",
  "data": {
    "credentials": {
      "accessKeyId": "STS.NUxxxxxxxx",
      "accessKeySecret": "xxxxxxxxxxxxxxxx",
      "securityToken": "CAISxxxxxxxx",
      "expiration": "2026-06-05 12:00:00"
    },
    "oss": {
      "bucket": "private-domain-drive",
      "region": "cn-hangzhou",
      "endpoint": "oss-cn-hangzhou.aliyuncs.com",
      "rootPrefix": "shared/"
    },
    "stsBroker": {
      "accessKeyId": "LTAIxxxxxxxx",
      "accessKeySecret": "xxxxxxxxxxxxxxxx",
      "endpoint": "sts.cn-hangzhou.aliyuncs.com",
      "roleArn": "acs:ram::1234567890123456:role/your-oss-role",
      "roleSessionName": "private-domain-drive-session",
      "durationSeconds": 3600,
      "policy": "{}"
    },
    "user": {
      "userId": "admin",
      "displayName": "admin",
      "role": "admin",
      "account": "admin"
    },
    "capabilities": {
      "list": true,
      "download": true,
      "upload": true,
      "delete": true,
      "preview": true
    },
    "constraints": {
      "multipartUploadThresholdBytes": 10485760,
      "textPreviewMaxBytes": 524288,
      "allowedPreviewExtensions": [
        "jpg",
        "jpeg",
        "png",
        "gif",
        "pdf",
        "txt",
        "md"
      ]
    }
  }
}
```

#### 错误样例

body 非法：

```json
{
  "code": "BAD_REQUEST",
  "message": "Request body must be a JSON object",
  "requestId": "req-bootstrap-002"
}
```

STS 配置缺失：

```json
{
  "code": "SERVICE_UNAVAILABLE",
  "message": "Missing STS_ASSUME_ROLE_ARN",
  "requestId": "req-bootstrap-003"
}
```

#### 备注

1. 当前实现使用演示账号校验：admin/123456、member/123456（权限相同）。
2. STS 申请依赖以下环境变量：
   - `ALIBABA_CLOUD_ACCESS_KEY_ID`
   - `ALIBABA_CLOUD_ACCESS_KEY_SECRET`
   - `STS_ASSUME_ROLE_ARN`
   - `STS_ROLE_SESSION_NAME`（有默认值）
3. 默认 STS 有效期由 `STS_DURATION_SECONDS` 控制，默认 `3600` 秒。
4. 服务端签发 STS 时会尽量附带最小化 Policy，限制到指定 bucket 与 `rootPrefix`。
5. 日常再次打开 App：优先本地 stsBroker 直连阿里云 STS 刷新；/session/refresh 仅作兜底。
6. 文件上传下载不经过本接口，也不经过业务后端中转。

### 3.3 刷新临时凭证

#### 接口说明

当 STS 临时凭证即将过期或已过期时，客户端调用本接口重新申请临时凭证。
一期刷新接口只返回新的 `credentials`，不重复下发用户信息、OSS 配置与能力描述。

#### Method

`POST`

#### URI

`/api/v1/session/refresh`

#### 入参

当前实现不强制要求 Body。

| 参数名 | 参数类型 | 参数中文描述 | 是否必填 | 其他校验要求 |
| --- | --- | --- | --- | --- |
| - | - | 本接口当前无业务入参 | - | 后续若接入真实会话，可扩展 sessionToken / refreshToken |

#### 出参

外层仍遵循统一响应结构。`data` 字段如下：

| 参数名 | 参数类型 | 参数中文描述 |
| --- | --- | --- |
| credentials | object | 新的 STS 临时凭证对象 |
| credentials.accessKeyId | string | 临时 AccessKeyId |
| credentials.accessKeySecret | string | 临时 AccessKeySecret |
| credentials.securityToken | string | 临时安全令牌 |
| credentials.expiration | string | 凭证过期时间（yyyy-MM-dd HH:mm:ss） |

#### 出参样例

```json
{
  "code": "OK",
  "message": "success",
  "requestId": "req-refresh-001",
  "data": {
    "credentials": {
      "accessKeyId": "STS.NUyyyyyyyy",
      "accessKeySecret": "yyyyyyyyyyyyyyyy",
      "securityToken": "CAISyyyyyyyy",
      "expiration": "2026-06-05 13:00:00"
    }
  }
}
```

#### 错误样例

```json
{
  "code": "SERVICE_UNAVAILABLE",
  "message": "Missing ALIBABA_CLOUD_ACCESS_KEY_ID",
  "requestId": "req-refresh-002"
}
```

#### 备注

1. 刷新成功后，客户端应整体替换本地缓存的 STS 凭证。
2. 若刷新持续失败，客户端应引导用户重新初始化会话（重新走 bootstrap / 重新登录）。
3. 本接口不返回 `capabilities`；若角色能力可能变化，客户端应额外调用能力查询接口或重新 bootstrap。
4. 当前实现与 bootstrap 使用同一套 STS 签发逻辑与配置依赖。

### 3.4 查询当前用户能力

#### 接口说明

返回当前用户在客户端应展示的操作能力，以及可访问根前缀。
该接口用于：

- 页面按钮显隐控制
- 高风险操作前置判断
- 会话恢复后的能力刷新

最终文件访问控制仍以 OSS 鉴权为准。

#### Method

`GET`

#### URI

`/api/v1/me/capabilities`

#### 入参

无 Query、Path、Body 参数。

| 参数名 | 参数类型 | 参数中文描述 | 是否必填 | 其他校验要求 |
| --- | --- | --- | --- | --- |
| - | - | 本接口无业务入参 | - | 后续接入登录态后，可基于 Authorization 识别当前用户 |

#### 出参

外层仍遵循统一响应结构。`data` 字段如下：

| 参数名 | 参数类型 | 参数中文描述 |
| --- | --- | --- |
| userId | string | 用户 ID |
| role | string | 用户角色 |
| rootPrefix | string | 当前用户可访问根前缀 |
| capabilities | object | 客户端能力开关 |
| capabilities.list | boolean | 是否允许列举文件 |
| capabilities.download | boolean | 是否允许下载 |
| capabilities.upload | boolean | 是否允许上传 |
| capabilities.delete | boolean | 是否允许删除 |
| capabilities.preview | boolean | 是否允许预览 |

#### 出参样例

```json
{
  "code": "OK",
  "message": "success",
  "requestId": "req-capabilities-001",
  "data": {
    "userId": "demo-user",
    "role": "member",
    "rootPrefix": "shared/",
    "capabilities": {
      "list": true,
      "download": true,
      "upload": true,
      "delete": true,
      "preview": true
    }
  }
}
```

#### 备注

1. 一期不区分管理员与普通成员，文件操作能力一致。
2. 即使客户端显示可删除，若 STS Policy / RAM 未授权，OSS 仍会拒绝删除。
3. 一期所有成员默认具备 list / download / upload / delete / preview，不区分角色。
4. `rootPrefix` 与 bootstrap 返回的 `oss.rootPrefix` 语义一致，客户端应以该前缀作为文件空间根。

## 4. 非服务端接口边界说明

以下能力**不属于 FC 接口**，由客户端使用 STS 凭证直连 OSS 完成：

| 能力 | 调用方 | 鉴权依据 | 说明 |
| --- | --- | --- | --- |
| 文件列表 | 客户端 -> OSS | STS | 列举 `rootPrefix` 下对象 |
| 文件上传 | 客户端 -> OSS | STS | 小文件直传，大文件分片上传 |
| 文件下载 | 客户端 -> OSS | STS | 直连下载对象 |
| 文件删除 | 客户端 -> OSS | STS | 由云端最终鉴权 |
| 文件预览读取 | 客户端 -> OSS | STS | 受预览白名单与大小限制约束 |

相关客户端约束默认值：

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| multipartUploadThresholdBytes | 10485760（10MB） | 超过阈值建议分片上传 |
| textPreviewMaxBytes | 524288（512KB） | 文本预览最大读取大小 |
| allowedPreviewExtensions | jpg,jpeg,png,gif,pdf,txt,md | 预览扩展名白名单 |

## 5. 调用时序建议

### 5.1 冷启动进入文件空间

1. 客户端完成本地登录态准备（一期可先做简化登录）
2. 调用 `POST /api/v1/session/bootstrap`
3. 缓存 `credentials`、`oss`、`user`、`capabilities`、`constraints`
4. 使用 STS 直连 OSS 拉取 `rootPrefix` 文件列表

### 5.2 凭证续期（方案 B 优先）

1. 客户端检测 `credentials.expiration` 临近过期
2. 优先使用本地缓存的 stsBroker 直连阿里云 STS AssumeRole
3. 替换本地 STS 凭证
4. 继续后续 OSS 操作

### 5.3 能力刷新

1. 会话恢复或权限可能变化时
2. 调用 `GET /api/v1/me/capabilities`
3. 更新 UI 操作入口显隐

## 6. 安全与实现备注

1. 客户端禁止内置长期高权限 AccessKey。
2. 可缓存短时 STS，以及最小化权限的 stsBroker；必须使用安全本地存储（Keychain / EncryptedSharedPreferences）。
3. STS Policy 应限制到指定 bucket 与 prefix，避免全桶高权限。
4. 删除等高风险操作需同时满足：
   - 客户端 `capabilities.delete = true`
   - OSS 云端鉴权通过
5. 一期可不强制接入 API 网关；若后续需要统一域名、限流、审计，再叠加网关层。
6. 当前服务端仍属于轻量骨架，`user` 与 `capabilities` 为配置/演示映射结果，后续接入真实身份体系时需保持本文件字段兼容，或同步升级版本。
