# 接口文档

## 1. 文档说明

本文档描述 Private Domain Drive 一期轻后端（阿里云函数计算 FC）对外 HTTP 接口。

一期服务端职责仅包括：

- 登录校验与会话初始化
- 首次登录强制改密与用户目录回写
- 登录成功后下发客户端 OSS 访问密钥（pdd-client）与 OSS 连接信息
- 用户能力信息下发
- 健康检查

文件列表、上传、下载、删除、预览等文件流量接口**不经过业务后端**，由客户端持登录下发的长期 OSS 访问密钥直连阿里云 OSS 完成。

> **BREAKING（v0.3.0）**：认证模型已从 STS 临时凭证切换为双 AKSK 直连。bootstrap 响应不再包含 `credentials`/`stsBroker` 等 STS 字段，`/api/v1/session/refresh` 接口已删除；服务端与客户端必须同批发布。

### 1.1 文档范围

| 范围 | 是否覆盖 |
| --- | --- |
| FC 控制面接口 | 是 |
| OSS 直连文件操作 | 否（仅说明边界） |
| 二期登录鉴权增强 | 仅备注，不作为一期正式契约 |

### 1.2 基础信息

| 项 | 说明 |
| --- | --- |
| 协议 | HTTP / HTTPS |
| 数据格式 | `application/json; charset=utf-8` |
| 路径前缀 | `/api/v1` |
| 部署形态 | 阿里云 FC HTTP 触发器 |
| 本地调试默认地址 | `http://127.0.0.1:9000` |

### 1.3 统一响应结构

所有业务接口均返回 JSON。成功与失败共用以下外壳字段：

| 参数名 | 参数类型 | 参数中文描述 | 是否必填 | 说明 |
| --- | --- | --- | --- | --- |
| code | string | 业务状态码 | 是 | 成功固定为 `OK` |
| message | string | 状态说明 | 是 | 成功一般为 `success` |
| requestId | string | 请求追踪 ID | 是 | 优先取 FC 请求 ID |
| data | object | 业务数据 | 否 | 仅成功时返回 |

成功响应外壳示例：

```json
{
  "code": "OK",
  "message": "success",
  "requestId": "req-20260810-0001",
  "data": {}
}
```

失败响应外壳示例：

```json
{
  "code": "BAD_REQUEST",
  "message": "Request body must be a JSON object",
  "requestId": "req-20260810-0002"
}
```

### 1.4 统一错误码

| code | HTTP 状态码 | 含义 | 典型场景 |
| --- | --- | --- | --- |
| OK | 200 | 成功 | 正常返回 |
| BAD_REQUEST | 400 | 请求参数错误 | body 非 JSON 对象、缺少 account/password |
| UNAUTHORIZED | 401 | 身份校验失败 | 账号或口令错误 |
| NOT_FOUND | 404 | 路由不存在 | 路径或 method 不匹配 |
| SERVICE_UNAVAILABLE | 503 | 服务暂不可用 | 必填 `PDD_*` 环境变量缺失、OSS 读写失败 |
| INTERNAL_ERROR | 500 | 服务内部错误 | 未捕获异常 |

### 1.5 通用约定

1. 请求与响应字段统一使用 **camelCase**。
2. 时间字段使用 `yyyy-MM-dd HH:mm:ss` 字符串，例如 `2026-06-05 12:00:00`。
3. bootstrap 通过 body 中的 account / password 校验 OSS 用户配置文件（固定对象键为 `config/users.json`，位于网盘展示目录之外）；密码以 scrypt 哈希保存；暂不强制 Authorization Header。
4. 客户端拿到下发的 OSS 访问密钥后，文件读写权限最终以 OSS / RAM Policy 鉴权结果为准；bootstrap 返回的 `capabilities` 仅用于 UI 能力展示收敛。
5. pdd-client 密钥的权限由 RAM 授权策略限制在配置的 bucket + rootPrefix 范围。
6. 客户端仅在会话内存中持有下发的访问密钥，不落盘、不持久化；冷启动或密钥失效时引导重新登录换取新密钥。

## 3. 接口详情

### 3.1 健康检查

#### 接口说明

用于探活与运行时基础信息查询。可供本地调试、部署验收、监控探测使用。不依赖 OSS 凭证配置，不访问 OSS。

#### Method

`GET`

#### URI

`/api/v1/health`

#### 入参

无 Query、Path、Body 参数。

| 参数名 | 参数类型 | 参数中文描述 | 是否必填 | 其他校验要求 |
| --- | --- | --- | --- | --- |
| - | - | 本接口无业务入参 | - | - |

#### 出参

外层仍遵循统一响应结构。`data` 字段如下：

| 参数名 | 参数类型 | 参数中文描述 |
| --- | --- | --- |
| status | string | 服务状态，正常时为 `up` |
| version | string | 当前服务版本号 |
| runtime | string | 运行时标识，当前为 `nodejs20` |

#### 出参样例

```json
{
  "code": "OK",
  "message": "success",
  "requestId": "test-health",
  "data": {
    "status": "up",
    "version": "0.1.0",
    "runtime": "nodejs20"
  }
}
```

#### 备注

1. 该接口不校验业务身份。
2. 返回 200 仅表示 FC 函数可响应，不代表 OSS 凭证配置完整可用。
3. 若要验证凭证配置是否可用，应调用 `/api/v1/session/bootstrap`。

### 3.2 会话初始化 / 下发客户端 OSS 凭证

#### 接口说明

客户端在登录成功时调用。服务端校验账号口令成功后，从环境变量保管的两对长期 RAM AccessKey 中取出客户端密钥（pdd-client）并下发：

- 客户端 OSS 访问密钥（`clientCredentials`）
- OSS 连接配置
- 当前用户信息
- 能力描述（`capabilities`）
- 客户端约束配置（`constraints`）

该接口是一期进入网盘主流程的核心控制面接口。

#### Method

`POST`

#### URI

`/api/v1/session/bootstrap`

#### 入参

Content-Type 建议：`application/json`

Body 必须是 JSON 对象。

| 参数名 | 参数类型 | 参数中文描述 | 是否必填 | 其他校验要求 |
| --- | --- | --- | --- | --- |
| account | string | 成员账号 | 是 | 与 OSS 用户目录匹配 |
| password | string | 访问口令 | 是 | 与 OSS 用户 JSON 中的 password 一致 |
| platform | string | 客户端平台标识 | 否 | 建议传 macos 或 android |
| appVersion | string | 客户端版本号 | 否 | 建议语义化版本字符串，如 0.1.0 |

> 说明：account / password 用于 OSS 用户目录校验；用户目录固定为 `config/users.json`，password 必须是 `scrypt$<salt>$<derivedKey>` 哈希。platform、appVersion 便于后续版本兼容。

#### 出参

外层仍遵循统一响应结构。`data` 字段如下：

| 参数名 | 参数类型 | 参数中文描述 |
| --- | --- | --- |
| clientCredentials | object | 下发给客户端的 pdd-client 长期 OSS 访问密钥 |
| clientCredentials.accessKeyId | string | 客户端 AccessKeyId |
| clientCredentials.accessKeySecret | string | 客户端 AccessKeySecret |
| oss | object | OSS 访问配置 |
| oss.bucket | string | OSS Bucket 名称 |
| oss.region | string | OSS 地域，如 `cn-hangzhou` |
| oss.endpoint | string | OSS Endpoint |
| oss.rootPrefix | string | 允许访问的根前缀，如 `shared/` |
| user | object | 当前用户信息 |
| user.userId | string | 用户 ID |
| user.displayName | string | 用户显示名 |
| user.mustResetPassword | boolean | 是否要求用户修改密码 |
| capabilities | object | 客户端能力开关，仅用于 UI 收敛 |
| capabilities.list | boolean | 是否允许列举文件 |
| capabilities.download | boolean | 是否允许下载 |
| capabilities.upload | boolean | 是否允许上传 |
| capabilities.delete | boolean | 是否允许删除 |
| capabilities.preview | boolean | 是否允许预览 |
| constraints | object | 客户端行为约束 |
| constraints.multipartUploadThresholdBytes | number | 超过该字节数建议走分片上传 |
| constraints.textPreviewMaxBytes | number | 文本预览允许的最大字节数 |
| constraints.allowedPreviewExtensions | string[] | 允许预览的扩展名白名单 |

#### 出参样例

```json
{
  "code": "OK",
  "message": "success",
  "requestId": "req-bootstrap-001",
  "data": {
    "clientCredentials": {
      "accessKeyId": "LTAIxxxxxxxx",
      "accessKeySecret": "xxxxxxxxxxxxxxxx"
    },
    "oss": {
      "bucket": "private-domain-drive",
      "region": "cn-hangzhou",
      "endpoint": "oss-cn-hangzhou.aliyuncs.com",
      "rootPrefix": "shared/"
    },
    "user": {
      "userId": "admin",
      "displayName": "admin",
      "account": "admin"
    },
    "capabilities": {
      "list": true,
      "download": true,
      "upload": true,
      "delete": true,
      "preview": true
    },
    "constraints": {
      "multipartUploadThresholdBytes": 10485760,
      "textPreviewMaxBytes": 524288,
      "allowedPreviewExtensions": [
        "jpg",
        "jpeg",
        "png",
        "gif",
        "pdf",
        "txt",
        "md"
      ]
    }
  }
}
```

#### 错误样例

body 非法：

```json
{
  "code": "BAD_REQUEST",
  "message": "Request body must be a JSON object",
  "requestId": "req-bootstrap-002"
}
```

凭证配置缺失：

```json
{
  "code": "SERVICE_UNAVAILABLE",
  "message": "Missing required environment variables: PDD_CLIENT_OSS_ACCESS_KEY_ID",
  "requestId": "req-bootstrap-003"
}
```

#### 备注

1. 当前实现从 OSS 用户 JSON 校验账号口令；服务端以 `pdd-server` 密钥直连读取 `config/users.json`。
2. 登录下发依赖以下环境变量（缺任一项时返回 503，且不下发任何密钥）：
   - `PDD_SERVER_OSS_ACCESS_KEY_ID` / `PDD_SERVER_OSS_ACCESS_KEY_SECRET`（服务端读写用户目录）
   - `PDD_CLIENT_OSS_ACCESS_KEY_ID` / `PDD_CLIENT_OSS_ACCESS_KEY_SECRET`（登录下发）
3. 下发的密钥仅来自服务端环境变量，不落盘、不写日志；客户端仅在会话内存中持有。
4. 客户端退出登录或冷启动时丢弃密钥，需重新登录换取；不再提供任何凭证刷新接口。
5. 文件上传下载不经过本接口，也不经过业务后端中转。

### 3.3 修改当前用户密码

`POST /api/v1/session/password`

请求体必须包含 `account`、`currentPassword`、`newPassword`。新密码至少 8 个字符。服务端验证当前密码后更新 `config/users.json` 中的 scrypt 哈希并将 `mustResetPassword` 设为 `false`。成功返回统一 `OK` 信封；当前密码错误返回 `401 UNAUTHORIZED`，参数或长度不合法返回 `400 BAD_REQUEST`，OSS 读写失败返回 `503 SERVICE_UNAVAILABLE`。

```json
{
  "account": "admin",
  "currentPassword": "旧密码",
  "newPassword": "新的安全密码"
}
```

### 3.3 刷新临时凭证（已删除，BREAKING）

原 `POST /api/v1/session/refresh` 接口已随双 AKSK 直连改造删除。客户端持有的为登录下发的长期访问密钥，无需刷新；密钥被撤销或失效时，客户端应引导用户重新登录走 bootstrap 换取新密钥。请求该路径将返回 `404 NOT_FOUND`。

## 4. 非服务端接口边界说明

以下能力**不属于 FC 接口**，由客户端使用登录下发的长期 OSS 访问密钥直连 OSS 完成：

| 能力 | 调用方 | 鉴权依据 | 说明 |
| --- | --- | --- | --- |
| 文件列表 | 客户端 -> OSS | pdd-client AK | 列举 `rootPrefix` 下对象 |
| 文件上传 | 客户端 -> OSS | pdd-client AK | 小文件直传，大文件分片上传 |
| 文件下载 | 客户端 -> OSS | pdd-client AK | 直连下载对象 |
| 文件删除 | 客户端 -> OSS | pdd-client AK | 由云端最终鉴权 |
| 文件预览读取 | 客户端 -> OSS | pdd-client AK | 受预览白名单与大小限制约束 |

相关客户端约束默认值：

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| multipartUploadThresholdBytes | 10485760（10MB） | 超过阈值建议分片上传 |
| textPreviewMaxBytes | 524288（512KB） | 文本预览最大读取大小 |
| allowedPreviewExtensions | jpg,jpeg,png,gif,pdf,txt,md | 预览扩展名白名单 |

## 5. 调用时序建议

### 5.1 冷启动进入文件空间

1. 客户端完成本地登录态准备（一期可先做简化登录）
2. 调用 `POST /api/v1/session/bootstrap`
3. 在会话内存中持有 `clientCredentials`、`oss`、`user`、`capabilities`、`constraints`，不落盘
4. 使用下发的访问密钥直连 OSS 拉取 `rootPrefix` 文件列表

### 5.2 凭证失效

1. 客户端无需任何凭证刷新流程；长期密钥不存在过期刷新问题
2. 若 OSS 返回鉴权失败（密钥被撤销、签名不匹配等），客户端清除会话内的密钥
3. 引导用户重新登录，重新走 bootstrap 换取新密钥

## 6. 安全与实现备注

1. 客户端构建中不得内置 OSS 长期访问密钥；密钥由服务端保管、登录 bootstrap 下发。
2. 客户端仅在会话内存中持有下发的访问密钥，不落盘、不持久化；退出登录时清除。
3. pdd-client 密钥的 RAM 授权策略应限制到指定 bucket 与 prefix，避免全桶高权限。
4. 删除等高风险操作需同时满足：
   - 客户端 `capabilities.delete = true`
   - OSS 云端鉴权通过
5. 一期可不强制接入 API 网关；若后续需要统一域名、限流、审计，再叠加网关层。
6. 当前服务端仍属于轻量骨架，`user` 与 `capabilities` 为配置/演示映射结果，后续接入真实身份体系时需保持本文件字段兼容，或同步升级版本。
