# Proposal

## Why

回收站当前按"删除批次"组织：单次删除（含多选）把全部对象复制进同一个 `shared/.trash/<批次ID>/` 并写一个 manifest，回收站列表把每个批次虚拟成目录树展示。这带来三个体验问题：

1. 多选删除的文件在回收站里无法单独恢复或彻底删除——恢复与立即删除作用于整个批次；
2. 批次展示名固定为「已删除项目」/「已删除 N 项」，无法体现内容，用户难以定位想恢复的文件；
3. 先后删除同名内容时，回收站中会出现多个隐含条目，与"回收站里按文件名区分"的用户心智不符。

期望的回收站语义与桌面系统一致：删除即把该项移入回收站成为独立条目；回收站内重名时，在新条目的原文件名后追加时间戳。

## What Changes

- 删除（单文件/文件夹/多选）改为逐项建立回收条目：每项独立 `shared/.trash/<entryId>/payload/` 与 manifest，独立展示名、原路径、删除时间与 30 天保留期。
- 回收站条目展示名默认取原文件名；与回收站中既有条目重名时，在扩展名前追加 `_yyyyMMdd_HHmmss` 时间戳（文件夹直接追加在名称后），仍冲突时追加序号直到唯一。
- 回收站列表根层由"批次虚拟树"改为平铺条目列表：每个回收条目展示为一个条目（文件/文件夹），文件夹可进入浏览其删除前结构，恢复与立即删除仍作用于整个条目。
- 多选删除的非阻塞进度与部分失败反馈维持现有口径，总进度跨全部条目累计。
- 存量批次条目兼容展示：旧 manifest 无需迁移，仍按单个条目渲染，恢复/彻底删除照常可用。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `recycle-bin`: "删除内容移入回收站"、"用户可以浏览和恢复回收内容"、"用户可以立即删除回收内容"三条 Requirement 从"批次"语义改为"每项独立条目 + 重名时间戳"，并新增重名命名规则场景。

## Impact

- 客户端代码（client/ 子仓库）：
  - `lib/shared/state/app_controller.dart`：删除入回收站按项建条目、重名时间戳命名、`BatchDeletePreview` 携带选中条目。
  - `lib/features/workspace/presentation/recycle_bin_page.dart`：根层平铺条目列表 + 文件夹钻取浏览。
- 无服务端改动；无接口契约变化；OSS 存储结构不变（仍为 `shared/.trash/<entryId>/payload/` + manifest）。
- 文档同步：`docs/Flutter架构设计.md`、`docs/技术文档.md` 中回收站相关描述从批次口径改为条目口径。
