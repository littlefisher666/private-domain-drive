## Context

文件目录浏览基于 OSS 前缀模拟目录，客户端直连 OSS（rootPrefix 为 `shared/`），服务端仅承担登录鉴权与密钥下发。OSS 软链接是对象级能力，无法对 key 前缀建立链接，因此别名必须是应用层的虚拟目录。项目已有将网盘内部元数据放入点前缀目录的先例（回收站 `shared/.trash/`、相册 `shared/.gallery/`），客户端密钥已有 `shared/` 全前缀读写权限，服务端无需参与。

## Goals / Non-Goals

**Goals:**

- 在 `shared/` 下渲染虚拟目录别名，别名可挂载到任意层级（含根目录），进入别名等价于浏览目标目录前缀
- 别名内的上传、下载、删除、移动等操作全部作用于真实目标路径
- 提供别名创建（右键/长按真实文件夹条目，可选挂载位置）与删除（右键/长按别名条目）入口
- `links.json` 读写全部由客户端用登录下发的密钥完成

**Non-Goals:**

- 不支持别名指向别名（目标必须是真实存在的目录前缀；挂载位置选在某个别名目标下视为挂载到该真实前缀，允许）
- 不支持跨 rootPrefix（如 `config/`）建立别名
- 不引入服务端接口改动、不使用 OSS 原生 Symlink 对象
- 不提供别名管理的专门页面（仅条目级操作菜单）

## Decisions

### 1. 元数据位置：`shared/.aliases/links.json`

对比过 `config/` 下由服务端在 bootstrap 下发：别名属于网盘空间的内容组织，且创建/删除是客户端高频交互，走服务端会破坏"FC 仅轻量鉴权"的定位并新增接口。放 `shared/.aliases/` 与 `.trash/`、`.gallery/` 同构，客户端现有密钥可直接读写，点前缀隐藏约定自动生效。

### 2. 数据模型

```json
{
  "version": 1,
  "links": [
    { "id": "uuid", "name": "家庭照片", "targetPrefix": "shared/家庭资料/照片/", "parent": "shared/", "createdBy": "当前登录用户名", "createdAt": "ISO-8601" }
  ]
}
```

- `id` 用 UUID：名称可改（重命名别名不改引用），删除按 id 定位
- `targetPrefix` 存储完整真实前缀（含 `shared/` 与结尾 `/`），进入别名时直接用该前缀 ListObjects，不做二次解析
- `parent` 为别名的挂载层级（完整目录前缀，含结尾 `/`），决定别名条目在哪个层级渲染；缺失时按会话根目录解析（兼容根目录版本的存量表）
- `createdBy` 记录创建时的登录用户名，取自登录会话，仅用于展示"链接是谁建的"，不做权限判断；旧版本客户端写入的无此字段条目按空值展示
- `version` 字段预留结构演进

### 3. 读写时机与并发控制

- **读**：浏览任意目录层级时与目录列表并行拉取 `links.json`（小对象，单次 GET 成本可忽略），按当前层级过滤渲染；对象不存在（404）视为空表；解析失败按空表处理并记录日志，不阻塞浏览
- **写**：创建/重命名/删除别名时整文件 PUT 覆盖，写前复查 ETag 实现乐观并发控制（读表→应用本端变更→复查最新 ETag→PUT；发现他端已写入则重读、重新应用本端变更后重试，与相册 manifest 的既有方案同构——原生上传不支持条件写，If-Match/412 需双端原生插件扩展，一期不引入）；仍失败则提示用户稍后再试
- 一期为单一共享空间、低频操作，整文件覆盖 + 乐观锁足够，不引入分片或增量结构

### 4. 导航与操作映射

- 导航栈节点增加"别名节点"类型：携带 `name` 与 `targetPrefix`，ListObjects 使用 `targetPrefix`，标题显示别名名称
- 上传、下载、删除、移动、新建文件夹等目录内操作统一从当前导航节点取真实前缀，天然作用于目标路径，操作层无需感知别名
- 移动到别名目录下（以别名为移动目标）等价于移动到 `targetPrefix` 下；批量操作复用同一映射
- 进入别名时记录挂载层级作为返回位置，从别名直接后退返回挂载层级；其余导航（子目录、面包屑）与普通目录一致

### 5. 别名条目语义

- 渲染：别名在其挂载层级（`parent` 匹配当前浏览路径）与真实条目合并排序，用链接角标区分；作为该层级的可见条目，计入所在层级条目统计（区别于被隐藏的点前缀条目）
- 别名条目的详情/属性信息中展示创建者（`createdBy`，缺失显示为空），不改变操作权限

- 删除别名条目 = 从 `links.json` 移除该条目，不触碰目标目录内容，需二次确认但文案区别于"移入回收站"
- 重命名别名 = 仅改 `links.json` 中 `name`
- 别名条目不提供移动、上传入口（根目录级操作不作用于别名本身）

### 6. 创建与校验

- 入口：右键（桌面）/长按（移动）任意**真实文件夹**条目 →"创建链接" → 先输入名称（默认取文件夹名，可修改），再用目录选择对话框选拼挂载位置（默认当前所在层级，可上溯到任意祖先层级，禁止选目标文件夹自身）；名称与位置确认后写入
- 创建时以当前登录用户名填充 `createdBy`，仅作为展示信息，不参与校验与权限判断
- 校验规则：
  - 目标必须是当前 rootPrefix 下真实存在的前缀（通过 ListObjects prefix + delimiter 验证），别名因非真实前缀天然被排除
  - 挂载位置必须是 rootPrefix 下的真实目录层级（含根目录；选别名条目视为挂载到其目标真实前缀），挂载位置不得为目标文件夹自身
  - 别名名称不得与挂载层级现有真实条目或其他同级别名重名（忽略大小写）
  - 名称非空、不以点开头、不含 `/`
- 失效处理：目标目录后续被删除或移走时，别名保留并渲染为可进入状态，进入时提示"目标目录不存在"，用户可删除该别名

## Risks / Trade-offs

- [多端并发写 `links.json` 互相覆盖] → 写前复查 ETag + 冲突重读重试（与相册 manifest 同构）；操作低频，剩余窗口毫秒级可接受
- [目标目录被移动/删除导致别名失效] → 保留别名并在进入时明确提示，提供删除入口；不做创建时硬校验之外的重定向猜测
- [`links.json` 手工损坏] → 解析失败按空表降级并记录日志，浏览不受阻塞；损坏的表内容不自动覆写（写操作前先重读，仅在用户主动变更时覆盖）
- [所有 shared 客户端均可修改别名表] → 一期为单一共享空间，视为预期行为，不引入按用户隔离的别名权限

## Migration Plan

无存量数据迁移：`links.json` 不存在即空表，客户端首次创建别名时写入。回滚 = 删除 `shared/.aliases/links.json` 即恢复原状，客户端旧版本对未知点前缀目录本就隐藏，无兼容负担。
