## Context

客户端当前直接通过 OSS 删除文件；目录和批量删除会先递归列举对象。Bucket 已配置 `shared/.trash/` 在最后修改时间满 30 天后自动删除。Android 与 macOS 已通过同一 Flutter 状态控制器和官方 OSS SDK 桥接层提供列举、复制和删除能力。

## Goals / Non-Goals

**Goals:**

- 将单项和批量删除安全地改为软删除，并在两端提供一致的查看与恢复体验。
- 恢复时不覆盖用户当前已有的对象。
- 仅使用现有 OSS 与 STS 能力，不增加后端或数据库。

**Non-Goals:**

- 不提供手动彻底删除、跨用户审计中心、版本历史或到期时间修改。
- 不处理应用外直接执行的 OSS 删除。

## Decisions

### 回收批次采用自描述 manifest

每次删除生成一个 UUID 批次：`shared/.trash/<id>/manifest.json` 与 `payload/`。manifest 保存原始路径、对象键、目录标记、删除时间和 30 天到期时间；payload 保存对象相对于 `shared/` 的路径。恢复和回收站列表只依赖 manifest，不需要数据库。

### 先复制、后删除

所有源对象复制成功后才删除对应源对象。单个对象的复制失败不会删除源对象；批量操作返回每个源对象的成功或失败结果。此顺序优先保证防误删，代价是故障期间可能留下可清理的孤立回收副本。

### 回收站隔离为保留前缀

普通工作区列表过滤 `.trash/`；回收站页面仅列举该前缀的批次目录。恢复时若目标路径已存在，使用同级 `（已还原）` 后缀递增命名，绝不覆盖现有对象。

### 两端入口

macOS 在侧栏功能区提供“回收站”；Android 在“我的”页进入独立路由。两端复用同一页面、状态和 OSS 操作，不增加平台原生代码。

## Risks / Trade-offs

- [目录或批量操作对象较多] → 继续按 OSS 1000 对象上限分批，页面显示处理结果。
- [复制后删除失败] → manifest 保留已归档对象；源对象仍在，用户可再次删除或由后续回收站恢复处理。
- [生命周期异步执行] → 界面显示预计清理日期，不承诺精确时刻。
- [对象路径冲突] → 恢复路径自动使用不冲突名称，保护当前文件。

## Migration Plan

1. 发布客户端后，新的删除操作开始写入回收站前缀。
2. 既有直接删除内容不迁移且无法恢复。
3. 回滚客户端只会隐藏新入口；已存在的回收站对象继续由 Bucket 生命周期规则清理。
