## Context

文件工作区已经以独立的路径集合维护多选状态，并具备批量下载、批量删除、全选、范围选择及 Android 长按选择能力。当前 UI 通过显式“选择”按钮进入多选模式，只有进入后才为所有条目渲染复选框和批量工具栏。

本次调整参考百度网盘桌面端的选择模型：文件区域表头常驻选择入口，条目复选框在悬浮或已选时显示，用户无需理解或主动进入一个额外模式。批量下载与删除的业务编排不变。

## Goals / Non-Goals

**Goals:**

- 让桌面用户通过表头或条目复选框一步开始批量选择。
- 在不干扰单击选中、双击打开等普通浏览操作的前提下提供悬浮复选框。
- 用三态表头复选框准确表达未选、部分选中和全部选中。
- 批量状态只呈现下载和删除两个业务动作，并继续遵守账号能力权限。
- 缩略图卡片只保留缩略图和文件名，将释放出的空间用于扩大内容预览。
- 将桌面单文件操作集中在列表和缩略图共用的右键菜单，避免卡片、列表和详情区重复展示。
- 将右侧详情区保持为纯预览与元信息区域，并收敛桌面上传入口。
- 保持列表、缩略图以及触屏端选择状态共享同一套路径集合。

**Non-Goals:**

- 不修改批量下载、目录递归展开、批量删除或传输队列实现。
- 不增加批量分享、移动、复制、重命名等动作。
- 不实现跨目录或跨页面持续选择。
- 不改变普通单击选中、双击打开或预览的浏览语义。

## Decisions

### 1. 以“选中集合是否为空”驱动桌面批量态

桌面端不再要求用户先进入显式选择模式。表头复选框和条目复选框都直接更新现有路径集合；集合从空变为非空时展示批量动作，清空后恢复普通状态。现有多选状态对象继续复用，避免引入第二套选择模型。

Android 仍保留长按进入多选的模式标志，因为触屏没有 hover，普通点击还需要与打开条目区分；进入多选后所有条目显示复选框，清空或退出后恢复普通点击行为。

备选方案是保留“选择”按钮并同时增加常驻复选框，但会形成两个功能重复的入口，因此不采用。

### 2. 表头复选框常驻并使用三态语义

文件区域表头左侧始终展示复选框和目录加载摘要：未选择时为未勾选，部分选择时为中间态，当前已加载条目全部选中时为勾选。点击未勾选或中间态执行当前目录全选，点击已勾选状态清空选择。

“全选”仅作用于当前目录已经加载的条目。当前 OSS 目录列表一次返回当前层级结果，因此摘要可显示“已全部加载，共 N 项”；若后续引入分页，应同步将文案和全选语义改为“已加载范围”。

备选方案是保留独立“全选/重新全选”文字按钮，但它与复选框重复且不符合参考交互，因此移除。

### 3. 条目复选框采用覆盖层并阻止事件穿透

桌面列表和缩略图条目在鼠标悬浮时于左上角显示复选框；条目已选时，即使鼠标移开也保持显示。复选框点击只切换选择，不触发条目的普通单击选择、双击打开或预览行为。未悬浮且未选时不占用显著视觉空间。

悬浮状态应收敛在条目级可复用组件中，避免让整个页面因鼠标移动而重建。列表与缩略图共享相同的显示条件和切换回调，但可以根据布局采用不同的定位尺寸。

### 4. 批量工具区只承载状态摘要、下载和删除

存在选择时，表头展示“已选 N 项”，并按权限展示下载、删除按钮。下载和删除按钮继续调用现有批量处理逻辑；权限不足的动作不显示。清空选择通过点击已勾选的表头复选框完成，不再提供独立“退出选择”按钮。

普通状态下原有上传、新建、刷新、视图切换和单文件动作不属于批量工具区，不受“仅保留下载和删除”约束。

### 5. 缩略图卡片只展示缩略图和文件名

桌面缩略图卡片移除文件格式、文件大小及底部的打开、下载、重命名、删除按钮，只保留尽可能大的缩略图区域和单行文件名。悬浮或选中时出现的左上角复选框属于选择控件，不占用固定卡片内容高度。

普通状态下单击卡片仍选中条目，双击仍打开文件或文件夹。卡片本身不承载单文件操作按钮，具体操作由列表和缩略图共用的右键菜单提供。

备选方案是在缩略图上叠加悬浮操作按钮，但这会与左上角复选框争夺悬浮空间、遮挡图片并提高误点删除的风险，因此不采用。

### 6. 单文件操作统一进入桌面右键菜单

桌面列表和缩略图条目都响应辅助点击，并在指针位置打开同一套上下文菜单。菜单始终作用于被右键点击的单个条目，不隐式作用于其他批量选中项；批量下载和批量删除继续只从顶部批量工具区发起。

文件菜单按类型和权限提供“预览/打开、下载、重命名、删除”，文件夹菜单提供“打开、重命名、删除”。不支持文件夹直接单文件下载时不显示下载项；无权限的重命名或删除项不显示。删除继续复用现有二次确认，右键菜单不得绕过业务与权限检查。

普通单击仍用于更新右侧详情预览，双击仍作为桌面平台的标准打开快捷方式。右侧详情预览只展示缩略图、名称、类型、大小、路径和更新时间，移除操作按钮及“能力”文案，避免与右键菜单重复。

Android 没有右键输入，继续保留现有“更多”底部菜单作为触屏端单文件操作入口。

### 7. 桌面上传只保留文件页工具栏入口

应用标题栏右上角的“上传”与文件页工具栏“上传文件”功能重复，因此移除标题栏按钮及对应回调。文件页工具栏继续作为桌面上传的唯一常规入口；移动端上传面板、系统分享导入及空目录引导属于不同场景入口，不受影响。

## Risks / Trade-offs

- [悬浮复选框与双击打开事件冲突] → 复选框使用独立点击区域并消费指针事件，条目其余区域保持原交互。
- [表头全选状态与目录刷新后条目不一致] → 以当前 Future 返回的可见条目和路径集合实时计算三态，目录切换继续清空选择。
- [空目录无法表达全选状态] → 空目录表头保持未勾选且禁用复选框，并显示 0 项。
- [触屏端没有 hover] → Android 继续使用长按进入多选，并在多选期间常显条目复选框。
- [局部 hover 状态增加组件复杂度] → 抽取轻量条目选择覆盖组件，避免在列表与网格重复维护事件规则。
- [右键操作对新手可发现性较弱] → 保持双击打开的标准桌面行为，并让右侧详情预览随普通单击更新；不在卡片内恢复重复按钮。
- [右键目标与批量选择并存时语义不清] → 右键菜单明确只作用于指针目标，批量操作只从顶部批量工具区执行。
- [文件名过长影响卡片高度] → 文件名固定单行并使用省略号，完整名称可在右侧详情面板查看。

## Migration Plan

1. 调整选择状态方法，使桌面复选框可以直接切换路径，并支持表头全选/清空。
2. 用常驻三态表头替换现有“选择 / 全选 / 退出选择”工具条。
3. 为桌面列表和缩略图条目接入悬浮/已选复选框覆盖层，保留 Android 长按交互。
4. 精简桌面缩略图卡片，为列表和缩略图接入共用右键菜单，并将右侧详情区改为只读。
5. 移除桌面标题栏上传入口，保留文件页工具栏上传。
6. 更新现有批量操作 widget 测试，并验证普通单击、双击、右键操作、上传、下载、重命名和删除行为未回归。

变更只涉及客户端交互，可通过恢复原选择工具条和条目渲染方式回滚，不涉及数据迁移。
