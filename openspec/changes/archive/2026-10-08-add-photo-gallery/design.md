# 设计：相册功能（add-photo-gallery）

## Context

客户端目前按 OSS 前缀（文件夹层级）浏览文件，已有目录内缩略图浏览能力（`oss-image-thumbnails`：OSS 图片处理按需加载、签名请求、磁盘缓存与淘汰、详情预览）。相册功能需要跨文件夹聚合全部照片并按拍摄时间组织，这要求一份独立于目录结构的照片索引，以及"缩略图常显、原图按需"的两层数据策略。

约束：服务端 FC 零改动；不引入数据库服务端；双端共用大部分代码，平台差异收敛在基础设施适配层；UI 以已确认的效果图为准（`docs/ui/相册-安卓端.html`、`docs/ui/相册-macOS端.html`）。

## Goals / Non-Goals

**Goals:**

- 全量照片按拍摄日期时间线浏览，列表秒开（一次索引请求 + 缩略图缓存）
- 原图仅在需要时进入本地，缓存占用有硬上限
- macOS 提供接近原生图库的交互：框选/勾选、⌘C 复制、⌘V 粘贴上传、悬浮栏自动隐藏
- 服务端与现有目录浏览行为零影响

**Non-Goals:**

- 站内对外分享链接（二期另立提案）
- 人脸/地点智能分类（信息栏仅展示 EXIF 已有字段，不做识别）
- 系统级定时清理任务（launchd / WorkManager）
- 系统相册 App 集成（iCloud 式缩略图注入，平台不开放，已排除）
- 视频在线播放格式转码（视频仅缩略图 + 原文件下载）

## Decisions

### D1：照片索引 = OSS 清单对象 + 客户端本地副本（推荐路线 B）

- OSS 存一份索引清单对象（`.gallery/index/photos.json`），记录每张照片的：对象 key、拍摄时间、文件大小、所在目录、媒体类型、视频缩略图 key、索引版本号。客户端登录后拉取清单，存入本地 SQLite 作为浏览数据源。相册内部对象（清单、缩略图）统一收敛在 `.gallery/` 点前缀目录下，避免与用户自建目录撞名（同回收站 `.trash/` 约定）
- **备选**（已否决）：客户端每次进相册页递归 ListObjects 扫描——文件夹多时需几十次 API 请求、秒级延迟，且每次进入都重复付出
- 写入策略：单用户私域盘场景，上传完成钩子做"读-改-写"整个清单对象；写前带上读取时的 ETag 做乐观并发，冲突（他人同时上传）时退避重试，多次冲突后标记索引为"待修复"，下次进入相册页提示并后台全量扫描重建。单文件清单索引记录丢失可自愈，不做逐条合并
- 索引条目包含清单版本与最后扫描时间，客户端以此判断是否需要提示重建

### D2：拍摄时间 = EXIF DateTimeOriginal 优先，文件时间兜底

- 图片上传时客户端解析 EXIF（新增 exif 解析依赖）；无 EXIF（截图、聊天保存图）回退文件修改时间。时间在**上传时解析一次并写入索引**，浏览时不重复解析
- 时区按本地时间记录展示（个人盘场景，不做跨时区归一化）
- 视频拍摄时间优先取媒体元数据，兜底文件时间

### D3：缩略图两套来源，URL 即区分

- **图片**：直接对原图对象 URL 追加 OSS 图片处理参数（`x-oss-process=image/resize,w_400/quality,q_80`），不落任何缩略图对象。同一对象"带参 = 缩略图、不带 = 原图"，天然区分
- **视频**：OSS 无实时截帧能力，上传前客户端截取一帧（新增 video_thumbnail 类依赖），作为独立对象上传到 `.gallery/thumbs/<原对象key>.jpg`，索引记录映射
- **超大图片**（原图超过 OSS 图片处理大小限制，约 20MB，实测 DSC 原片报 ImageTooLarge）：走与视频相同的 `.gallery/thumbs/` 独立对象路线，但缩放由客户端本地完成（macOS NSImage / Android BitmapFactory 桥），上传时与上传并行生成；存量条目进入相册页时后台补齐（下载原图 → 本地缩放 → 上传 → 索引记映射，单个失败跳过）。加载时优先取索引缩略图对象，不再请求 OSS 图片处理
- 缩略图的网络加载、鉴权、磁盘缓存复用 `oss-image-thumbnails` 已有机制（同一套请求签名与缓存组件），不另起炉灶
- 分辨率档位：列表 400px、大图查看降级态 1200px，常量收敛在一个文件

### D4：原图缓存 = 独立缓存目录 + SQLite 状态表

- 下载原图存入独立缓存目录（不复用缩略图磁盘缓存），SQLite 表记录：对象 key → 本地文件路径、文件大小、最后访问时间、缓存时间
- **云朵角标语义**：表中有记录 = 已缓存（无角标），无记录 = 未缓存（角标）。下载完成写入记录后通过状态通知刷新列表，角标即时消失
- 未缓存点开：先以 1200px 缩略图放大展示，同时走现有传输队列下载原图，完成后无缝替换并写缓存记录

### D5：缓存清理 = App 内执行 + 双策略兜底

- 触发时机：App 启动时、相册页下载原图前（容量预检）。不引入 launchd/WorkManager——App 未打开期间缓存只是静默占用磁盘，无及时性要求
- 双策略：①超过 N 天（默认 30，可配置）未访问的缓存条目清理；②缓存总容量超过上限（默认 5 GB，可配置）时按 LRU（最后访问时间）清理至阈值以下。策略②保证占用有硬上限，使"不及时清理"无害化
- 清理动作 = 删本地文件 + 删 SQLite 记录（角标回归），不触碰 OSS 数据

### D6：导航与路由双端共用，平台交互走适配层

- `home_shell.dart` 的 Tab 列表与侧边栏列表各加"相册"项，共用同一 route（`/gallery`）与页面组件；Android 底部 Tab 由 4 变 5
- 框选（拖拽矩形选择）、⌘C/⌘V、⌘A 全选、鼠标静止隐藏悬浮栏为桌面专属交互，通过平台判断开关并收敛在 gallery 模块内；Android 提供系统分享（share sheet），macOS 不做分享
- Android 查看器沿用现有图片预览页交互（左右滑动切换、推移动画、纯黑沉浸式），切换范围收敛为当前日期分组；上下滑不再用于切换，改为上滑呼出、下滑收起条目详情面板（基础/来源/位置分组，与 macOS 信息栏同构）；不引入预览页没有的双指缩放等新交互

### D7：macOS 剪贴板走平台桥

- ⌘C：将选中照片原图（未缓存的先下载）写入系统剪贴板为图片数据（macOS 经现有 platform channel 模式新增桥接方法，与 `native-oss-storage` 的桥接契约风格一致）
- ⌘V：相册页监听粘贴事件，读取剪贴板图片写入临时文件后走现有上传管线（自然触发索引增量更新），无 UI 提示
- 快捷键不在任何按钮上标注（用户已确认）

### D8：删除后索引增量清理，与上传对称

- 照片/视频删除成功后（无论从相册页还是文件页发起），客户端对 OSS 清单做"读-改-写"移除对应条目并更新本地索引副本，机制复用 D1 的 ETag 乐观并发与冲突退避；存在缩略图映射的条目（视频、超大图片）同时删除 OSS 上的 `.gallery/thumbs/<key>.jpg` 缩略图对象，本地原图缓存记录与缓存文件一并删除
- 缩略图对象删除失败不阻塞删除流程，残留对象无害（清单中已无映射，不再被引用），可由下次全量扫描重建自然消化
- 清单写入冲突超限时与上传路径一致，标记待修复、进入相册页提示并后台重建

### D9：视频条目不在线播放，点击展示截帧并提供下载

- 与 Non-Goal（不做格式转码）一致：双端点击视频条目进入查看器后仅展示截帧缩略图，配"不支持在线播放"提示与下载原图操作；下载完成写缓存记录（角标消失）但不自动播放
- 视频不参与照片的连续浏览序列，避免"切到视频却无法播放"的断裂体验

## Risks / Trade-offs

- [清单对象读-改-写并发冲突丢索引条目] → ETag 乐观并发 + 退避重试 + 冲突超限后全量扫描重建，最终一致可自愈
- [首建索引时照片多、扫描慢] → 全量扫描放后台并展示进度提示，扫描完成前相册页显示"建立索引中"占位，不影响其他功能
- [无 EXIF 图片时间不准（回退文件时间≠拍摄时间）] → 可接受的展示误差；用户可后续手动调整（不在本期范围）
- [视频缩略图截帧增加上传耗时] → 截帧在上传队列中与上传并行准备，失败时索引记录为"无缩略图"，列表显示占位图
- [原图缓存占用用户磁盘] → 容量上限 + LRU 双策略硬性兜底（D5）
- [⌘V 粘贴非图片内容] → 静默忽略，不弹错误
- [清单对象损坏（JSON 解析失败）] → 视为待修复状态，自动触发全量扫描重建

## Migration Plan

纯新增能力，无数据迁移。上线顺序：

1. 客户端合入索引、相册页、查看器、缓存管理
2. 已有存量照片在用户首次进入相册页时全量扫描建索引（一次性，带进度提示）
3. 回滚 = 客户端回退版本；OSS 中的 `.gallery/` 对象对新版本无依赖，残留无害

### 前缀迁移（内部修订）

早期实现曾把清单与缩略图放在会话根下的 `index/`、`thumbs/` 普通目录，存在与用户自建目录撞名的风险；已收敛为 `.gallery/index/`、`.gallery/thumbs/` 点前缀形式。存量数据迁移经 OSS 服务端复制（`CopyObject`）一次性完成、改写清单映射并删除旧对象，迁移代码不保留在客户端。全量扫描跳过 `.gallery/` 前缀（不收录为照片），点前缀对象在文件浏览中统一隐藏。
