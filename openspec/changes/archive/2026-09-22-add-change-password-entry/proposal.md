## Why

`POST /api/v1/session/password` 接口本身已支持任意登录用户校验当前密码后改密，但客户端目前仅在 `mustResetPassword: true` 的强制改密场景下暴露改密页面，用户无法在设置中主动修改自己的密码。现在补齐这一入口，使已有接口的通用能力对用户可见。

## What Changes

- 客户端设置中新增"修改密码"入口，进入主动改密页面。
- 主动改密页面复用既有改密表单交互：当前密码、新密码、确认密码输入，本地校验两次输入一致且新密码不少于 8 个字符。
- 主动改密调用既有 `POST /api/v1/session/password` 接口，成功后提示并返回设置页；服务端会自动将 `mustResetPassword` 置为 false。
- 主动改密成功后本地会话的 `mustResetPassword` 同步更新为 false（正常情况下本就为 false，防御性更新）。
- 不改变既有强制改密访问拦截逻辑，服务端接口无任何改动。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `password-reset-flow`: 新增"客户端设置提供主动修改密码入口"需求，允许已登录用户在设置中主动完成密码修改，与强制改密流程共用同一接口与表单校验规则。

## Impact

- 客户端：设置页新增入口与导航、主动改密页面（可复用/抽取既有改密表单）、FC API 客户端无新增接口、状态管理与测试。
- 服务端：无改动，接口与用户目录格式维持现状。
- 文档：接口文档无变化；如客户端功能文档描述了设置项，需补充修改密码入口说明。
