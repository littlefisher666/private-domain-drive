## Context

强制改密能力已上线：服务端提供通用的 `POST /api/v1/session/password`（校验当前密码、新密码至少 8 位、scrypt 回写 `config/users.json` 并清除 `mustResetPassword`），客户端 `ChangePasswordPage` 已实现当前密码/新密码/确认密码表单、本地校验与会话状态更新，但目前仅在强制改密场景可达，成功后固定清除状态并导航到文件空间。设置页 `SettingsPage` 已存在，具备分组列表入口的展示形态。

## Goals / Non-Goals

**Goals:**

- 已登录用户可在设置中主动进入改密页并完成密码修改。
- 最大化复用既有改密表单、校验规则与 API 调用，不新增服务端接口。
- 主动改密成功后的导航行为与强制改密场景正确区分。

**Non-Goals:**

- 不改动服务端接口、用户目录格式与强制改密访问拦截逻辑。
- 不引入找回密码、旧密码找回邮件、改密后强制重新登录等能力。
- 不做改密历史记录或密码强度策略（除既有 8 位最小长度）。

## Decisions

### 复用 `ChangePasswordPage`，以模式参数区分成功后行为

给 `ChangePasswordPage` 增加一个模式/来源参数（如 `forced`，默认 true 以兼容既有强制改密路由）：强制模式下成功后清除 `mustResetPassword` 并进入文件空间（现状行为）；主动模式下成功后提示成功并返回设置页。表单校验、错误展示与 `changePassword` 调用完全共用。

- 备选方案是新建独立页面，但表单与调用逻辑完全重复，违反最小实现原则；抽共享 widget 再包两个页面层数也多于一个参数。

### 主动模式成功后的会话状态防御性更新

主动模式下改密成功同样将本地会话的 `mustResetPassword` 置为 false（正常情况下本就是 false）。若用户是在强制改密状态通过某种路径到达此页，该更新可避免本地状态与服务端标记不一致。

### 设置入口位于账户/安全相关分组

在 `SettingsPage` 新增"修改密码"入口（列表项），点击导航到主动模式的改密页。入口对 Android 与 macOS 共用，无平台分支。

## Risks / Trade-offs

- [改密页被强制改密用户在未完成改密时通过设置页到达并返回，绕过拦截] → 强制改密状态下不展示设置入口或入口不可达（设置页本身仅在文件空间内可达，而强制改密状态下用户无法进入文件空间，风险天然不存在；实现时不在改密页提供返回设置的操作，仅提供完成后返回）。
- [同一页面两种模式的行为差异引入回归] → 强制模式为默认参数值，既有路由与测试不受影响；为主动模式补充独立测试。

## Migration Plan

1. 客户端新增路由/入口与模式参数，发布新客户端版本即可。
2. 无服务端部署、无数据迁移；回滚仅需回退客户端版本。
