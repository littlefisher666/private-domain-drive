## Context

工作区当前仅区分列表与缩略图浏览模式。缩略图网格的最大卡片宽度和纵横比为固定值，且浏览偏好中尚未记录尺寸。Android 与 macOS 共用工作区页面和 `AppController`，可通过同一状态及布局参数实现一致体验。

## Goals / Non-Goals

**Goals:**

- 使用户能在缩略图模式选择小、中、大三档尺寸。
- 在 Android 与 macOS 提供可发现、风格匹配的选择入口。
- 将选择保存为本地偏好，并在启动时恢复。
- 保持现有中档的视觉密度作为默认值。

**Non-Goals:**

- 不提供连续滑杆、手势缩放或键盘快捷键。
- 不变更列表模式、图片预览页、服务端接口或 OSS 鉴权架构。
- 不为每档位改变 OSS 缩略图请求规格。

## Decisions

- 使用 `ThumbnailSize` 枚举表达 small、medium、large 三档，并由该枚举集中定义网格参数。桌面端按最大卡片宽度自适应；移动端固定为小图三列、中图两列、大图一列，确保窄屏上每档的实际卡片尺寸不同。
- 将尺寸状态置于 `AppController`，使用现有 `SharedPreferences` 实例写入与恢复。这样工作区重建、平台切换和应用重启后都保持一致；偏好写入失败仅影响后续恢复，不影响当前会话。
- 在既有目录头部中仅当缩略图模式激活时展示尺寸入口：Android 使用图标弹出菜单，macOS 使用紧凑的文本分段控件。两端均用小、中、大标签，避免额外的学习成本。
- 默认使用 medium，并维持当前约 180–190px 的卡片宽度；small 约 130px，large 约 260px。缩略图请求继续使用现有 320px OSS 处理规格，避免切换档位触发重复网络读取。

## Risks / Trade-offs

- [大档位在窄屏上可见项目更少] → 由用户主动选择，布局仍依赖最大交叉轴范围以自动换列。
- [大档位可能放大已有缩略图的像素] → 保持内容完整展示；如未来实际清晰度不足，可单独评估按档位提高 OSS 请求规格。
- [旧偏好值或本地存储不可用] → 仅接受已知枚举值，其他值回退到 medium。
