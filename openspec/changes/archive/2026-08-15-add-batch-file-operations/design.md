## Context

客户端当前在 `workspace` 中以单选状态驱动详情与单文件操作；下载直接读取完整对象字节后由用户逐文件选择保存位置。`transfer` 已有任务展示、重试和取消界面，但任务进度由模拟计时器驱动，未编排真实 OSS 请求。删除文件夹使用递归列举与逐对象串行删除。

本变更服务于 macOS 的文件整理与批量下载场景，同时保持 Android 可通过长按进入多选。文件内容继续由客户端使用 FC 下发的 STS 临时凭证直连 OSS，业务服务端不参与文件流量。

## Goals / Non-Goals

**Goals:**

- 建立跨列表和缩略图复用的多选状态及批量操作入口。
- 让每个被下载文件成为独立、可观测、可取消和可重试的真实任务。
- 以受控并发执行上传和下载，并允许用户在传输中心设置总并发数。
- 让批量删除能处理目录展开、对象去重、部分失败和本地目录状态刷新。

**Non-Goals:**

- 不生成 ZIP 或其他压缩包。
- 不实现批量移动、复制、重命名、回收站或服务端异步任务。
- 不提供跨应用重启的未完成网络传输恢复；仅持久化并发设置。

## Decisions

### 1. 用独立的多选状态取代单选状态复用

在 `AppController` 或 workspace 专属状态中维护按对象路径索引的选中集合及是否处于多选模式；原有 `selectedItemListenable` 继续只服务桌面详情面板和普通浏览，避免混合单选、双击打开与多选的语义。

macOS 提供“选择”入口、复选框、Cmd 切换、Shift 范围选择和 Cmd+A；Android 由长按进入模式，点击切换选中。两端都显示已选数量、全选和取消操作。

备选方案是在现有单选值中保存多个对象；它会破坏详情面板和现有点击语义，且不能表达多选模式，因此不采用。

### 2. 批量下载按文件创建子任务，不生成 ZIP

批量下载先由用户选择一次目标目录，随后为每个已选文件创建一个下载任务和共享批次标识。选中的文件夹通过 OSS 分页列举递归展开为文件任务，并按其相对于当前下载根的路径在本地创建目录，以保留文件夹结构；重复选择的对象路径只创建一个任务。任务以流式 HTTP 响应写入临时文件，完成后原子移动到目标目录；同名文件自动添加序号，避免弹窗逐项阻塞批次。

批次汇总由子任务状态计算，显示总数、完成、失败、排队和进行中数量。取消批次会取消未启动任务，并向运行中任务发送取消信号、清理临时文件。失败任务保留在传输中心并可独立重试。

备选方案是将多个文件压缩为 ZIP；这会引入临时磁盘空间、压缩进度与格式兼容性问题，超出一期范围，因此不采用。

### 3. 采用上传下载共用的总并发队列

传输调度器维护待执行队列和运行任务集合，以全局并发上限限制上传、下载合计的活动任务数。默认上限为 3，用户可在传输中心设置 1 至 5，并持久化到本地偏好。设置变更立即影响后续调度：提高时立即补充任务，降低时不强制中断已运行任务。

备选方案是分别设置上传、下载并发；一期场景任务量有限，两个设置会增加理解与调度复杂度，也可能总并发失控，因此不采用。

### 4. 批量删除采用“展开、去重、分批请求、汇总结果”

删除前递归列举选中文件夹下的全部对象，并与直接选中的对象按对象键去重，确认界面展示受影响文件夹和对象数量。OSS 删除按多对象删除 API 的单批限制切分；需要对目录列举支持分页，以避免遗漏大目录。请求允许部分成功，系统保留失败对象并展示可重试结果，同时刷新当前目录、树目录缓存与多选状态。

备选方案是继续逐对象串行删除；它实现简单但在批量和大目录场景中延迟过高，且难以形成有效进度反馈，因此不采用。

## Risks / Trade-offs

- [批量传输占用内存或磁盘] → 下载采用流式写入临时文件，队列最大并发限制为 5，取消/失败清理临时文件。
- [STS 在长批次期间过期] → 每次启动任务前检查并刷新凭证；已失败任务可在刷新后重试。
- [多对象删除非原子且可能部分失败] → 在 UI 中明确汇总成功/失败数量，保留失败项及重试入口，不宣称全部回滚。
- [目录展开耗时且对象数量大] → 分页列举、批量删除，并在确认/执行阶段展示准备中或执行中状态。
- [本地同名文件覆盖用户数据] → 默认自动改名，不覆盖目标目录已有文件。
- [平台目录授权差异] → 将目标目录选择和文件写入隔离为平台基础设施接口，并在 Android 上使用平台许可的目录访问方式。

## Migration Plan

1. 先引入真实任务调度器与流式 OSS 下载，保留现有单文件入口并改为创建任务。
2. 接入多选 UI 和批量操作，将删除实现替换为可分页、多对象批处理路径。
3. 在 macOS 与 Android 验证权限、取消、重试、同名文件和部分失败路径后发布。
4. 如出现传输异常，可关闭批量入口并保留单文件下载/删除；无需数据迁移，删除失败对象仍留在 OSS。

## Open Questions

- Android 的目标目录选择将依据当前 Flutter 插件能力决定使用目录选择器还是系统文档树授权；实施时需在真机确认。
- 大批次任务列表是否需要在后续版本做持久化，目前本变更仅持久化并发设置。
