# Proposal

## Why

传输中心的下载记录目前只保留文件名、目标路径、总大小和最终状态，没有任何时间字段：用户无法判断文件是什么时候加入队列、什么时候开始下载、什么时候完成，也看不到耗时和平均速度；失败与进行中的下载在重启后直接丢失，历史记录难以用于排查和复盘。补充任务生命周期时间线与性能指标，可以让传输中心从“当前状态面板”变成可追溯的传输记录。

## What Changes

- 为传输任务（上传、下载共用）新增生命周期时间戳与统计字段：首次入队时间、首次开始时间、最近一次开始时间、终态时间、累计实际传输时长、累计传输字节、尝试次数。
- 明确计时口径：时长使用单调时钟统计；排队与暂停时间不计入传输耗时；平均速度按累计传输字节与累计传输时长计算。
- 传输中心已结束（成功、失败、已取消）任务卡片展示文件大小、结束时间、耗时与平均速度；排队中任务展示已等待时长，进行中任务展示已用时。
- 新增任务详情视图，展示“加入队列 → 开始下载 → 完成/失败/取消”的完整时间线、排队耗时、总耗时、传输耗时、平均速度、文件大小与尝试次数。
- 传输历史记录从单个 `SharedPreferences` JSON 迁移到本地 SQLite（复用项目已有 `sqflite`），按任务增量写入，避免整表重写；失败任务纳入历史记录。
- 历史记录按结束时间保留最近 90 天，并以最多 20000 条为安全上限，超限时淘汰最旧记录；首次升级时一次性导入旧 `SharedPreferences` 历史，旧数据保留为回滚快照。
- 历史列表按页加载（每页 300 条），类型筛选计数基于保留范围内的全部历史与内存中未结束任务，不因分页而缺失。
- 同状态内排序改为基于入队时间/结束时间的稳定排序，重启后顺序不再依赖内存列表顺序。
- 本次不持久化排队中和下载中的下载任务，不记录每次尝试的独立时间线，不提供批次汇总、历史搜索与导出；这些留作后续增强。
- 同步更新 `docs/技术文档.md` 与 `docs/Flutter架构设计.md` 中关于传输状态模型、历史持久化与卡片展示的描述。

## Capabilities

### New Capabilities

- `transfer-task-history`: 传输任务生命周期时间戳、耗时与平均速度统计、终态历史记录的持久化与保留策略。

### Modified Capabilities

- `transfer-queue-management`: 传输中心任务卡片的展示内容与排序口径调整，增加已结束任务的结束时间、耗时、平均速度，以及排队中/进行中任务的已等待/已用时展示；允许非进行中任务展示平均速度（与现有“非进行中不展示速度”约束区分）。

## Impact

- 数据模型：`client/lib/features/transfer/domain/transfer_task.dart` 新增字段与 JSON 序列化。
- 队列与调度：`client/lib/features/transfer/application/transfer_queue.dart` 增加计时、累计字节、终态写入与历史持久化 v2；`transfer_controller*.dart` 调整重试与取消时的字段维护。
- 展示层：`client/lib/features/transfer/presentation/transfer_tasks_page_build.dart` 及其卡片组件调整；新增任务详情视图。
- 本地存储：新增 SQLite 历史表与访问层，启动恢复改为异步分页读取；从 `transfer_history:v1` 一次性迁移旧数据并保留旧键作为回滚快照。
- 测试：补充计时、重试、暂停、SQLite 持久化、迁移、保留清理、分页与历史排序相关测试。
- 文档：`docs/技术文档.md`（10.2 下载策略、10.3 状态模型）、`docs/Flutter架构设计.md`（传输持久化与展示）。
- 不受影响：OSS 原生传输链路、并发配置、前台保活通知、上传断点续传策略。
